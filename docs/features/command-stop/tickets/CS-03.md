# CS-03: SIGTERM/SIGKILL 단계와 잔존 확인

명세: [../SPEC.md](../SPEC.md) s1. Scheduling·의존성·resource·write scope·gate supplier: [../PLAN.json](../PLAN.json)의 CS-03. 상태·실제 assignment는 Root 운영 기록에서만 관리한다.

## 제공할 동작

stop episode가 SIGINT → (10 s) SIGTERM → (5 s) SIGKILL → (5 s 확인) 단계를 자동으로 이어 가고, 각 단계마다 tracked 구성원을 다시 조사해 남은 자식·재부모화된 후손에 같은 신호를 보낸다. 결과의 `signals`에 보낸 신호·시각·대상이, `residual`에 남은/보고만 하는 프로세스가 담긴다. setsid로 다른 session에 간 후손은 신호를 받지 않고 보고되며, 그것만 남으면 `unknown`(`left_session_descendants`)이다.

## 수락 기준

- CS-AC-04: SIGINT를 무시하면 SIGINT 뒤 10 s에 SIGTERM, 다시 5 s에 SIGKILL, 그 뒤 최대 5 s 확인. 단계 동안 상태 `stopping`, 종료 시 `exited`와 마지막 종료 signal. 각 신호와 전송 시각이 journal에 있다.
- CS-AC-05: 신호는 command의 tracked 구성원에 가고, 종료 뒤 남은 같은 pgrp·subreaper 후손에도 같은 단계가 적용되며 결과로 보고된다. 추적 밖(다른 session)은 신호 없이 보고만, 확인하지 못한 범위는 `unchecked`로 명시한다.
- CS-AC-20(부분): `command_stop_signal`의 단계·시각·대상·실패, `residual`이 기록된다.

## 계약과 맥락

- SPEC "단계와 타이머", "추적 범위와 잔존 확인", "신원·신호 불변식" 4, 5, 7. CS-02의 episode 뼈대를 확장한다(`StopPolicy`로 시간 주입).
- 정지(T) 상태 구성원은 SIGCONT를 보조 신호로 받는다. EPERM/ESRCH는 구성원별 기록, 모두 EPERM이면 즉시 `unknown`(`permission_denied`)이다(이후 `unknown` 전체 의미 고정은 CS-04).
- main이 이미 끝났는데 tracked 후손이 남은 상태에서도 stop은 후손에 단계를 적용한다(소유자 `exited`는 lifetime 종료 때만).

## 검증

Seam S2(실제 PTY) + S7(필요 시 오류 주입). 독립 기대값: 정책 상수(줄인 값), 명령이 스스로 만든 종료 형태(128+n), `/proc`에서 읽은 후손 pid의 생존/소멸. 타이밍 단언은 상수 기반의 하한/허용 오차로 쓰고 시계를 mock하지 않는 실제 시간으로 확인한다(줄인 정책).

RED→GREEN 순서:
1. `bash -c 'trap "" INT; sleep 100'`: SIGINT 무시 → SIGTERM 단계에서 종료(code 143, signal 15). `signals` 순서 [SIGINT, SIGTERM], 간격이 `sigint_grace` 이상.
2. `trap "" INT TERM; sleep 100`: SIGKILL까지 가서 종료(137, 9). 총 시간이 정책 합 이내.
3. 후손: `bash -c 'trap "" INT TERM; sleep 100 & sleep 101 & wait'`에서 모든 후손이 종료되고 `residual.alive==[]`.
4. main 종료 후 남은 후손: `bash -c '(trap "" INT; sleep 100) & exit 0'`: main exit 0 뒤에도 후손에 단계가 적용되어 `exited`, `exit_code` 0, `signals`가 main 종료 이후 전송을 포함.
5. 다른 session 후손: `bash -c 'setsid sleep 100 & exit 0'`: 후손에 신호 없음, 결과 `unknown`(`left_session_descendants`), `residual.left_session`에 pid, 후손은 살아 있다(테스트가 정리).
6. 정지(T) 구성원: `kill -STOP`된 대상에 SIGCONT가 보조로 기록되고 종료한다.

## 범위 밖과 중단 조건

idempotency, `unknown` 정정, 인가, Manager 도구, 실험은 하지 않는다. 다른 session 후손을 신호 대상으로 넣어야 한다는 결론이 나오면(사용자 결정 영역) 멈추고 `needs_reroute`. 시한을 늘리거나 단계를 건너뛰어 테스트를 통과시키지 않는다.
