# CS-04: 반복 stop의 멱등성, `unknown`, 늦은 종료 정정

명세: [../SPEC.md](../SPEC.md) s1. Scheduling·의존성·resource·write scope·gate supplier: [../PLAN.json](../PLAN.json)의 CS-04. 상태·실제 assignment는 Root 운영 기록에서만 관리한다.

## 제공할 동작

같은 command_id의 stop episode를 하나로 유지한다. 진행 중 두 번째 요청은 같은 최종 결과를 기다리고, 끝난 뒤의 요청은 원래 결과(`repeat: true`)를 돌려주며 신호·타이머를 새로 만들지 않는다. SIGKILL 뒤에도 종료를 확인하지 못하거나 권한 오류로 신호를 보내지 못하면 `unknown`과 이유를 반환·기록하고 성공/종료로 표시하지 않는다. `unknown` 뒤 소유자가 종료를 나중에 관측하면 같은 episode를 `exited`로 정정하고(`corrected: true`, `history`에 정정 전 `unknown`과 이유) 새 신호는 보내지 않는다.

## 수락 기준

- CS-AC-10: 진행 중 동시 두 호출이 같은 최종 결과를, 종료 뒤 호출이 같은 결과를 반환하고 신호 단계·타이머를 새로 시작하지 않는다.
- CS-AC-18: SIGKILL 후 5 s에도 종료 미확인(또는 EPERM)이면 `unknown`+이유, 기록·표시, 명령은 수정·재실행 가능으로 보고되지 않고 새 명령은 계속 `terminal_command_running`.
- CS-AC-23(terminal): `unknown` 명령의 종료가 나중에 관측되면 `exited`로 정정, exit code·signal 채움, 정정 전 `unknown`과 이유가 이력·journal(`command_stop_corrected`)에 남고 정정이 새 신호를 만들지 않는다.
- CS-AC-20(부분): `unknown` 이유, 정정 이력, 반복 요청 수가 기록된다.

## 계약과 맥락

- SPEC "결과 계약"(`repeat`, `corrected`, `history`), "상태 전이"(unknown 처리, 소유자 선언 unknown은 정정 없음), "신원·신호 불변식" 4. `unknown`·`exited`·`stale`·미등록 id에는 새 신호가 없다(CS-D11).
- 정정 경로: `TerminalService._follow` 완료 시 CS-02가 연결한 `command_ended` hook이 episode 상태를 갱신한다.
- `stopping`/`unknown`의 표면화는 CS-02 구조를 따른다(`watch_state().running`은 true 유지).

## 검증

Seam S2(실제 PTY) + S7(오류 주입 `StopEnvironment`: `send`를 무효화하거나 `PermissionError` 발생). D 상태와 EPERM은 실제 PTY에서 안정적으로 만들 수 없어 주입이 필요하다(신규 seam, 2026-10-21 사용자 확정). 독립 기대값: 정책 상수, 주입한 오류, 테스트가 직접 확인한 프로세스 생존.

RED→GREEN 순서:
1. 진행 중 반복: SIGINT 무시 명령에 두 호출을 동시에 보내 같은 최종 결과, `signals`가 단일 집합(중복 전송 없음), 두 번째에 `repeat: true`.
2. 종료 뒤 반복: 원래 결과와 같고 신호 0건, 다른 프로세스 영향 없음.
3. `unknown`(SIGKILL 무효): `status==unknown`, `reason==still_alive_after_sigkill`, `watch_state` 상태 `unknown`, 새 `terminal` 명령은 `terminal_command_running`, 반복 stop은 신호 없이 같은 결과.
4. EPERM 주입 → 즉시 `unknown`(`permission_denied`), 구성원별 `failed` 기록.
5. 정정: 3의 대상이 나중에 종료(테스트가 실제로 종료) → episode `exited`, `corrected: true`, `history[0]`에 `unknown`과 이유, `signals` 개수 불변, journal `command_stop_corrected`.

## 범위 밖과 중단 조건

인가·Manager 도구·실험·bridge는 하지 않는다. 소유자가 선언한 unknown의 정정은 만들지 않는다(한계로 보고). `unknown`을 숨기거나 `exited`로 낮춰 통과시키지 않는다.
