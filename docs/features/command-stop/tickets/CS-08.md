# CS-08: free-work 취소 응답과 `/task` 상태에 실행 중 명령 표시

명세: [../SPEC.md](../SPEC.md) s1. Scheduling·의존성·resource·write scope·gate supplier: [../PLAN.json](../PLAN.json)의 CS-08. 상태·실제 assignment는 Root 운영 기록에서만 관리한다.

## 제공할 동작

free-work Task를 취소하면 응답 `{status:"cancelled", task_id, worker_notified}`에 `host_commands`(해당 Task의 아직 실행 중인 명령: `command_id`, `kind`, `owner`, `state`(`running|stopping|unknown`), `started_at`, `log_path`, `stop` 요약)가 붙고, 하나라도 있으면 `host_command_note`("취소는 명령을 멈추지 않는다. 멈추려면 `terminal` stop / `stop_command`")가 붙는다. 취소 뒤 Task가 닫혀도 `/task`(`snapshot()["task"]`, `workbench_status.task`)에 살아 있는 명령이 별도로 계속 보인다. 명령이 없거나 이미 끝났으면 `host_commands: []`이고 note가 없다. 취소 응답은 종료를 뜻하는 문구·상태를 쓰지 않는다.

## 수락 기준

- CS-AC-01: 실행 중이면 command_id와 `running`과 안내, 없거나 끝났으면 실행 중이라고 표시하지 않음.
- CS-AC-02(free-work 부분): 취소 뒤 명령이 도는 동안 `/task`는 `closed`이지만 명령 상태는 `running`으로 별도 표시. (실험 취소 부분은 CS-09.)

## 계약과 맥락

- SPEC "취소 응답", "명령 상태 표면". `TerminalService`에 `commands_for_task(task_id)`(끝나지 않은 명령 목록)를 두고, `TaskFlow`가 `terminal_runs`와 같은 방식의 주입 callable(`host_commands`)로 받는다. `task_id`가 `null`인 명령은 어떤 Task에도 붙지 않는다. `view()`는 저장 대상이므로 `host_commands`는 `task_view()`/`status_view()`/취소 응답 조립 시점에 계산하고 ledger에 쓰지 않는다.
- `contracts/ui_v1.py` docstring에 additive 필드를 기록한다(문서; `TASK_STATUSES` 불변).
- `flow_tasks.py`의 `_cancel`/`CANCEL_*` 문구와 `detail` 키는 기존 의미를 유지한다(통지 보류 문구와 충돌하지 않는다).

## 검증

Seam S1(기존 `test_task_flow` fixture로 만든 TaskFlow + 실제 `TerminalService`/PTY 명령 또는 `FakeHostPort`가 아닌 실제 실행 중 명령). 독립 기대값: 테스트가 만든 Task/명령 상태, BRIEF 안내 요건. `stopped`/`terminated` 같은 금지 문구는 부재를 단언한다.

RED→GREEN 순서:
1. 실행 중 `terminal` 명령이 있는 free-work Task 취소 → `host_commands[0]`에 `command_id`·`state:"running"`, `host_command_note`가 stop 방법을 안내, 응답에 종료 문구 없음.
2. 명령이 없거나 이미 끝난 Task 취소 → `host_commands == []`, note 없음.
3. 취소 뒤 `task_view()`가 `status:"closed"`이면서 `host_commands`는 `running`; 명령 종료 후 `[]`; 명령에 stop이 진행 중이면 `stopping`.
4. `task_id=null` 명령은 다른 Task의 `host_commands`에 나오지 않는다. `workbench_status.task`에도 같은 필드가 있다.

작성 범위: `src/workbench/backend/flow_tasks.py`, `src/workbench/backend/flow_terminal.py`(`commands_for_task`), `src/workbench/backend/service.py`(주입), `src/workbench/contracts/ui_v1.py`(docstring), `tests/backend/test_cancel_host_command.py`. `*_independent*` 제외.

## 범위 밖과 중단 조건

취소가 명령을 죽이게 하는 변경, Task 상태 값 추가, `task_id=null` fencing(CS-O01)은 하지 않는다. `FlowTask` 저장 필드를 늘려야 하면 멈추고 `needs_reroute`.
