# CS-09: 실험 host 명령 stop, `stopped` outcome, 취소와의 결합

명세: [../SPEC.md](../SPEC.md) s1. Scheduling·의존성·resource·write scope·gate supplier: [../PLAN.json](../PLAN.json)의 CS-09. 상태·실제 assignment는 Root 운영 기록에서만 관리한다.

## 제공할 동작

1. `TaskFlow`가 실행 중 실험의 host 명령을 `command_id=run_id`로 `CommandStopService` 등록부에 올린다(`HostShellPort`, 등록 시 읽은 `request_id`, 종료 관측 hook). Manager `stop_command`가 이를 멈춘다. Worker가 실험 명령을 stop하면 `refused: not_owner`.
2. 취소 없이 stop된 실험 run: 종료가 관측되면 분석·판정 없이 `last_result.outcome="stopped"`(`stopped_by`, `exit_code`, `signal`)로 닫고 Task는 `finished`. 저장소는 `complete_run(run_id, {outcome:"stopped", stopped_by, judgment:null,...})`(event kind 추가 없음). 자동 재시도·성공/실패 판정 없음. stop 표식은 첫 신호 직전에 붙는다. 신호 전에 명령이 스스로 끝났으면 평소 경로.
3. 취소와 stop 결합: `cancel_requested`로 호스트 종료를 기다리던 Task는 stop이 종료를 확인한 시점에 `cancelled`로 닫힌다(판정 없음). 종료가 `unknown`이면 닫히지 않고 `host_commands[].stop.reason`으로 이유가 보이며, 이후 종료가 관측되면 그때 닫힌다.
4. 실험 취소 응답 `cancel_requested`가 `CANCEL_WAIT_DETAIL`(취소는 멈추지 않음, `stop_command` 안내 추가)과 `host_commands`를 함께 준다.

## 수락 기준

CS-AC-02(실험 부분), CS-AC-06(Worker가 Manager 실험 명령 stop 거절), CS-AC-12, CS-AC-21, CS-AC-23(실험 Task가 늦은 종료 관측에서 닫힘), CS-AC-20(부분: 실험 `stopped` 요청자, `run_ended` 레코드).

## 계약과 맥락

- SPEC "실험 명령 stop과 outcome". 선행: CS-04(episode·unknown·정정), CS-05(`stop_command` 경로·인가·owner 매트릭스), CS-08(`host_commands` 항목 스키마와 취소 응답 조립). `_follow(task, run, port)`는 `shell_state=="exited"`를 소유 종료로 쓴다; `unknown` stop은 `run.collect`가 `running`을 돌려주므로 `_follow`는 계속 수집한다(변경하지 않는다).
- `_finish_stopped`는 `_judgment_unavailable`/`_finish_run`의 잠금·repository·`run_ended` 기록·`_notify_lifecycle("run_ended")` 관례를 따른다. `stopped` outcome 소비자(`last_result` 읽는 곳)가 있으면 목록화한다. 저장소 consumer가 `completed`를 성공으로 해석하는 곳을 발견하면 멈추고 `needs_reroute`(schema 변경은 승인 범위 밖).
- `flow_tasks.py` docstring의 "never killed" 정책 설명을 stop이 종료를 맡는 것으로 갱신한다(취소 의미는 불변).

## 검증

Seam S1(`test_task_flow` fixture 위 TaskFlow, 실제 host shell로 실험 명령 실행) + S2(Manager stop 경유 실제 신호). 독립 기대값: 테스트가 만든 실험 spec/명령, repository에서 직접 읽은 run event(`completed` + details), `last_result`, 판정 stage가 호출되지 않았다는 fake worker의 호출 0회.

RED→GREEN 순서:
1. 실행 중 실험에 Manager `stop_command` → `exited`, run은 `stopped`로 닫힘(`last_result`, repository `completed` details), Task `finished`, 분석 호출 0, 재시도 예약 없음, `stopped_by:"manager"`.
2. Worker가 실험 run_id를 stop → `refused: not_owner`, 신호 0.
3. 취소 후(`cancelling`) stop → 종료 관측 시 Task `cancelled`로 닫힘, 판정 없음; 취소 응답에 `host_commands`와 갱신된 detail.
4. stop `unknown`(S7 주입) → Task `cancelling` 유지, `host_commands[].stop.reason` 표시; 이후 종료 → 닫힘, 정정 이력.
5. 신호 전에 명령이 스스로 끝남 → `already_exited`, outcome은 평소 판정 경로(`stopped` 아님).
6. 등록부 정리: 실험 종료·Task 닫힘 뒤 `command_id`는 `already_exited`를 반환하고 메모리에 `run`/`port`를 붙잡지 않는다.
