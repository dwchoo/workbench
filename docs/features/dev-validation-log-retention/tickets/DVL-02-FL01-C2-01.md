# DVL-02-FL01-C2-01 — Esc 메뉴 닫힘 실패 조사·최소 수정

상위 ticket: [DVL-02](DVL-02.md). Core [FL-01](../../core-workbench/FOLLOWUPS.md)의 증상과 연결하되 같은 원인이라고 단정하지 않는다.
권한: [2026-10-10 진행 방향 동의](../../../../.workflow/dev-validation-log-retention/runs/blockers-20261010/authority.json).
기존 FL-01 제품 수정 제외를 이번 Esc 증상의 조사·필요한 최소 수정 범위에 한해 해제한다.
상태: 이번 최소 계측은 종료했지만 실패 원인은 미확정이다. 상위 DVL-02와 최종 통합 gate는 미완료다.

## 문제와 기존 근거

정밀 검증 after의 tmux/dash C2에서 manager OMP의 `esc_closed_menu=False`가 관측됐다.
[원 실패](../../../../.workflow/dev-validation-log-retention/runs/implement-p5-20261009/resume-result-dvl02-runtime02.json)를 유지한다.
별도 계측 cell은 original/optimized 모두 통과했지만 실패 당시 input/menu/frame trace가 없어 원인은 미확정이다.
[이전 probe](../../../../.workflow/dev-validation-log-retention/runs/implement-p5-20261009/resume-result-dvl02-c2-probe01.json)의 통과를 실패 해결로 쓰지 않는다.

## 이번 작업

1. 기존 C2 입력·menu predicate·screen/frame·PTY 전달 경계를 대조하고 최소 판별 항목을 정한다.
2. 전용 HOME/project/data/socket의 credential-free 실제 OMP와 scripted provider에서 한 cell을 계측한다.
3. 전송 누락, OMP 동작, 화면 관측 timing, 시험 predicate 오류를 구분한다. 임의 sleep 증가나 반복 성공만으로 해결하지 않는다.
4. 근거가 확인된 원인에만 최소 수정한다. 원인 미확정이면 기록·재개 조건을 반환하고 추측성 제품 수정은 하지 않는다.

## 검증·마감

- 입력→전달→메뉴 닫힘→다음 frame을 연결한 근거, 현재 후보·환경·argv·cleanup을 남긴다.
- 수정 시 독립 test_designer 회귀와 fresh reviewer, 영향을 받은 실제 cell 검증을 포함한다.
- 원 실패와 최초 실패/재실행을 모두 보존한다. probe 통과와 상위 정밀 suite 통과를 구분한다.
- DVL-02 마감은 원래 required 항목·시간 비교·최종 리뷰/통합 조건을 별도로 충족해야 한다.

Q01 기준 변경, proxy, 실제 raw 활성화, 사용자 OMP/DB/서비스·credential, 유료 모델, unrelated UI/terminal 기능 확대는 제외한다.

## 2026-10-10 계측 결과와 재개 조건

현재 제품 후보에서 실제 OMP 18.8.6·scripted provider·tmux/dash 원본 cell을 한 번 실행했다.
C1–C7은 모두 통과했고 manager/worker의 원 `esc_closed_menu` 판정도 참이었다.
manager Esc의 stdin → parser → backend 수락 → OMP PTY 전달 → 화면 frame 경계를 단조 시각으로 연결했다.
[원 실행·trace](../../../../.workflow/dev-validation-log-retention/runs/blockers-20261010/c2-probe01/result.json)와
[전용 namespace·소유 process 정리](../../../../.workflow/dev-validation-log-retention/runs/blockers-20261010/c2-probe01/cleanup.json)를 보존한다.
계측에 따른 timing 영향은 가능하므로 이번 통과로 간헐 실패가 없어졌다고 주장하지 않는다.

독립 테스트에서 발견한 긴 AF_UNIX 경로 사전 검사 순서만 probe에서 수정했고,
[재검증 5개](../../../../.workflow/dev-validation-log-retention/runs/blockers-20261010/c2-test02/result.json)는 모두 통과했다.
원 실행 후의 변경은 preflight 검사 위치 이동뿐이며 원 실행을 새 전체 후보의 실행으로 재표시하지 않는다.
제품 코드와 원 C2 입력·gap·3초 predicate는 변경하지 않았다.

원 실패가 재현되지 않아 제품 수정 근거는 없다. 다음 재개에는 실패 당시 같은 경계 trace 또는
구체적인 새 재현 조건이 필요하다. 근거 없는 반복 성공이나 sleep 증가로 원 실패를 닫지 않는다.
진단 probe·문서의 독립 리뷰/통합 기록과 상위 정밀 suite 판정은 별도 운영 기록에서 관리한다.


## 2026-10-11 사용자 승인: 근거 확보 전 보류

사용자는 “c2는 추천안대로 해주고”라고 결정했다. 실패 당시 경계 trace 또는 구체적인 새 재현 조건이 확보되기 전에는 추측성 제품 수정과 동일 성공 probe 반복을 보류한다.
원 실패·미확정 원인·상위 DVL-02 및 최종 통합 gate 미완료를 유지한다. 이는 C2 완료나 검증 기준 면제가 아니다. Q01과 무관한 이 보류는 후속 개발의 상태 기록에 남긴다.
