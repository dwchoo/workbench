# 사용해보면서 생긴 요구사항
- 일시 : 2026.10.29 1640 작성

## 문제 상황 요약
- Manager에게 작업 지시서를 전달했더니 너무 한번에 처리하려고 해서 worker가 많은 일을 하거나 worker가 잘 처리 못함.
- worker가 터미널을 사용해서 작업을 해야 하는데 직접 명령어를 실행하려는 문제 다시 발생

## Manager에서 필요한 개선
### 작업 지시서를 받거나 작업 명령을 받으면 작업 계획을 세워서 해야한다.
- 여러 상황에 멀티로 사용할 수 있는 스크립트를 만들어서 작업을 진행하면 안된다.
- 단일 스크립트 혹은 간단한 명령어로 처리할 수 있는 작업 단위로 나눠서 작업 계획을 만들고 그걸 worker에게 지시한다. 
- 가능하면 간단한 스크립트로 작업을 할 수 있게 작업을 나누고 각각에 대한 스크립트를 만들어서 worker가 실행하게 한다.
- 작업 계획은 omp의 todo로 기록하거나 필요하면 단일 md 파일를 만들어서 todo check box를 만들고 스스로 점검한다.

### 작업을 수행할 때 사용하는 수단
- 가능하면 shell script를 사용하거나 uv를 사용한 python script를 사용한다. 환경 설정에 영향을 주는 설치가 필요하면 반드시 사용자의 승인을 받는다.
- 만약 사용자가 설치나 셋팅을 요구할 때는 사용자에게 물어보고 승인을 받으면 그 세션에서는 알아서 계속 설치나 셋팅을 한다.
- tqdm 처럼 shell line을 갱신해서 터미널 창이 계속 안내려가게 작업해야 한다. 작업 할 때 마다 혹은 주기적으로 새롭게 라인을 입력해서 터미널이 계속 내려가게 작업하면 안된다.
- terminal 작업에는 반드시 현재 퍼센트 작업 종료 예상 시간, 경과 시간 등 현재 상태를 알 수 있게 하고 예상 시간을 파악할 수 있게 해야한다. 멈춰서 더이상 안돌아가는것 처럼 보이면 안된다.



## Worker 개선 사항
- Worker가 terminal 명령어를 스스로 실행하려고 시도하다가 block 당하는 경우가 있다. wb의 terminal shell을 사용하도록 잘 강제해야 한다. 아마 사용자가 ctrl+d로 omp를 종료하고 다시 실행할 때 뭔가 프롬프트가 잘 주입 안된거 같다. 평소에는 잘 안일어 나는거 같은데 omp를 다시 시작하면 뭔가 문제가 정확하게 작동 안하는거 같다.
- Worker는 복잡한 작업 요구를 받으면 manager에게 지시를 단순화 해달라고 요청해야 한다. worker는 작업을 모니터링하고 manager에게 보고하는 것이 목적다. worker는 코드를 작성하거나 판단을 하거나 하는 경우가 거의 없어야 한다. 판단과 코드 작성은 manager의 일이다.

## 이 요구사항을 읽고 반드시 해야 하는 것.
- 이 요구사항을 읽었으면 이 문서를 정리해서 옮기거나 해야 한다. docs에 그냥 두지 말고 이 추가 개발을 진행하고 문서화할 폴더에 넣어야 한다.
