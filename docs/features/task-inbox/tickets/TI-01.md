# TI-01: 의존성 고정·web 자산 packaging·xterm.js vendoring

명세: [../SPEC.md](../SPEC.md) s1. 의존성·자원: SPEC "Ticket 그래프"의 TI-01. 상태·실제 assignment는 orchestrator 운영 기록에서만 관리한다.
권장 executor: Sonnet(`model: "sonnet"`). Packaging·자산 복사이며 제품 동작이 없다.

## 제공할 동작

- `pyproject.toml` `dependencies`에 D-29의 고정 버전 10개(`aiohttp==3.14.5`, `aiohappyeyeballs==2.7.1`, `aiosignal==1.4.0`, `attrs==26.1.0`, `frozenlist==1.8.0`, `idna==3.20`, `multidict==7.2.0`, `propcache==0.5.4`, `typing-extensions==4.16.0`, `yarl==1.25.1`)를 기존 `pyte`·`wcwidth`와 함께 둔다.
- `src/workbench/hub/web/static/`을 package data로 wheel·sdist에 싣는다(`[tool.setuptools.package-data]`, `MANIFEST.in`). 설치 SPEC의 canonical 파일 분류·manifest hash 규칙이 이 자산을 알게 한다(`assets.py`·build hook·관련 정적 검사가 있으면 함께 갱신).
- xterm.js(`@xterm/xterm` 5.x 최신 안정판의 `xterm.js`·`xterm.css`, `@xterm/addon-fit`)를 npm registry 또는 GitHub release에서 내려받아 `static/vendor/xterm/`에 둔다. 각 package의 `LICENSE`(MIT)와 출처·버전·SHA-256을 적은 `static/vendor/xterm/SOURCES.md`를 함께 둔다. 내려받은 파일은 실행하지 않고 별도 빈 디렉터리에서 확인한 뒤 복사한다.
- `docs/features/task-inbox/DEPENDENCY-AUDIT.md`: 10개 Python package와 xterm 자산의 버전·출처·hash(설치된 `.venv`의 `RECORD`/wheel hash)·license·알려진 advisory 확인 방법과 결과. 온라인 advisory 확인은 SPEC 열린 결정 2가 정해질 때까지 `not_run`으로 적는다.

## 수락 기준

- P2-AC-37: wheel build 결과에 `workbench/hub/web/static/vendor/xterm/{xterm.js,xterm.css,addon-fit.js,LICENSE…}`가 있다. `pyproject.toml`이 정확히 위 버전으로 고정된다. 저장소 `src`에 `import mcp`/`from mcp`가 없다. 자산 파일에 외부 URL로의 runtime 참조(`https://` source map 등)가 없거나 제거·무해함이 기록된다.

## 계약과 맥락

SPEC "위치", "호환성". 설치 SPEC(`docs/features/workbench-installation/SPEC.md:117`, `:157`, `:183`). `build_support/assets.py`의 `BuildPy`. 새 Python 의존성은 이 10개 외에 없다. Node·npm은 다운로드·확인 도구로만 쓰고 runtime 의존성이 되지 않는다.

## 검증

TDD 예외(외부 자산 복사·설정): T9 정적 검사 테스트 `tests/hub/test_web_assets.py`를 먼저 쓰고(자산 없음으로 RED) 자산·설정 추가로 GREEN. wheel 검사는 `python -m build`가 없으면 기존 설치 테스트의 wheel build 방법(`tests/backend/installation`)을 따른다.

명령: `python3 tools/shm_tests.py -- env PYTHONDONTWRITEBYTECODE=1 PYTHONPATH=src .venv/bin/python -m unittest discover -s tests/hub -p 'test_web_assets*.py'`. 회귀: `… discover -s tests/backend/installation`(관련 asset·manifest 테스트).

작성 범위: `pyproject.toml`, `MANIFEST.in`, `build_support/`(필요 시), `src/workbench/hub/web/__init__.py`, `src/workbench/hub/web/static/vendor/**`, `tests/hub/test_web_assets.py`, `docs/features/task-inbox/DEPENDENCY-AUDIT.md`.
