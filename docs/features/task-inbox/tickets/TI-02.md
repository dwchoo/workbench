# TI-02: 인증 core — `auth.json`·`hub.sqlite3`·세션·API key·감사·`wb hub passwd`

명세: [../SPEC.md](../SPEC.md) s1. 의존성·자원: SPEC "Ticket 그래프"의 TI-02. 상태·실제 assignment는 orchestrator 운영 기록에서만 관리한다.
권장 executor: Opus(`model: "opus"`). 웹 로그인이 계정 전체를 지키는 유일한 장벽이다(ADR-0003).

## 제공할 동작

`src/workbench/hub/auth.py`(HTTP와 무관한 라이브러리):
- `PasswordStore`: `auth.json` 읽기·검증(형식 오류는 "비밀번호 없음"이 아니라 `auth_invalid`), `set_password`(auth.lock, 원자적 쓰기, generation+1), `verify`(scrypt n=2^15·r=8·p=1·dklen=32·maxmem 64 MiB, `compare_digest`), `generation()`, 길이 규칙.
- `HubDb`(`hub.sqlite3`, 0600, WAL): `sessions`, `api_keys`, `login_state`, `audit` schema와 migration 없는 v1 생성.
- 세션: `create(client_addr, user_agent, now)` → (token, csrf), `verify(token, now)`(만료 24 h 절대, generation 일치), `delete`, `delete_all_except(token)`, `reissue(token)`(비밀번호 변경 뒤).
- 로그인 지연: `delay_for(addr)`(SPEC의 `f(n)`), `record_failure`, `record_success`.
- API key: `issue(name, grade, scope, expires_days)` → 원문 1회, `verify(raw, now)` → principal 또는 거절 이유(`unknown`, `revoked`, `expired`, `malformed`), `revoke`, `list`, 마지막 사용 메모리 coalesce + `flush`, 시스템 key `rotate_system_key()`.
- `audit(event, actor, client_addr, detail)`·`list_audit(page)`·50,000건 상한.
- CLI `wb hub passwd [--stdin]`: Hub SPEC의 예약 거절을 대체한다. TTY 두 번 확인 / stdin 한 줄. Hub 자동 시작 없음. 감사 `password_changed{source:"cli"}`는 Hub가 다음에 `auth.json` generation 변화를 볼 때 기록한다(CLI는 `hub.sqlite3`를 쓰지 않는다: Hub 단일 writer).

## 수락 기준

- P2-AC-17(라이브러리): 시계를 주입해 24 h 경과 세션 거절, 비밀번호 변경 뒤 다른 세션 거절·현재 세션 재발급, 연속 실패 수에 따른 지연 값.
- P2-AC-18(store): 감사 행 형식, 입력 내용 필드 없음.
- P2-AC-19: 원문 key는 `issue` 결과에만, DB에는 hash만(테스트가 파일을 stdlib sqlite3로 읽어 원문 부재 확인). 폐기·만료 key `verify` 거절. `list`에 이름·scope·등급·마지막 사용·만료. 같은 key 연속 1,000회 verify가 거절되지 않음(rate limit 없음).
- `wb hub passwd --stdin`: `auth.json` 0600, scrypt 형식, generation 증가, 빈·짧은 입력 거절(exit 1, 파일 불변). TTY 불일치 입력 거절. Hub 프로세스 생성 없음.

## 계약과 맥락

SPEC "인증·세션·CSRF", "감사 기록", "API key", "CLI 추가". Hub SPEC 위치 규칙(`HubLayout`), `write_private_json`, `InstanceLock`. HB-10이 둔 `cmd_hub_reserved`의 `passwd` 분기를 대체한다.

## 검증

Seam T1a(라이브러리 + 파일) + T8(CLI subprocess). 독립 기대값: 테스트가 `hashlib.scrypt`로 직접 계산한 hash, SPEC 수치.

Behavior 순서:
1. `set_password` → 파일 형식·권한·generation.
2. `verify` 성공·실패(상수 시간 비교 사용은 코드 review로).
3. 세션 생성·검증·24 h 만료.
4. generation 변화 → 기존 세션 거절, `delete_all_except`·`reissue`.
5. 로그인 지연 함수와 성공 시 초기화(ip·global).
6. API key 발급(형식, hash만 저장)·검증·폐기·만료·malformed.
7. 마지막 사용 coalesce·flush.
8. 시스템 key 회전(이전 key 거절).
9. 감사 기록·상한.
10. `wb hub passwd --stdin`/TTY(PTY) CLI.

작성 범위: `src/workbench/hub/auth.py`, `src/workbench/hub/cli.py`(passwd), `src/workbench/backend/cli.py`(parser 인자), `tests/hub/test_hub_auth.py`, `tests/hub/test_hub_auth_cli.py`.

명령: `python3 tools/shm_tests.py -- env PYTHONDONTWRITEBYTECODE=1 PYTHONPATH=src .venv/bin/python -m unittest discover -s tests/hub -p 'test_hub_auth*.py'`. 회귀: `… discover -s tests/hub -p 'test_hub_service*.py'`(예약 명령 테스트 갱신).

독립 test_designer 검증 필수. 초점: 세션 token·key 원문이 DB·log·감사 어디에도 없음, 만료 경계(정확히 24 h), generation race(검증 중 비밀번호 변경), 손상 `auth.json`이 "비밀번호 없음"으로 오인되어 listener 정책을 우회하지 않음, 시스템 key가 일반 목록 폐기 대상이 아님, `hub.sqlite3`·`auth.json` 권한·symlink 거부.
