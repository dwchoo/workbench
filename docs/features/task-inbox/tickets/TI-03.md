# TI-03: `hub.toml`·web listener 수명·middleware·로그인

명세: [../SPEC.md](../SPEC.md) s1. 의존성·자원: SPEC "Ticket 그래프"의 TI-03(선행 TI-02). 상태·실제 assignment는 orchestrator 운영 기록에서만 관리한다.
권장 executor: Opus(`model: "opus"`). LAN에 열리는 listener, 세션·CSRF·Host/Origin 경계다.

## 제공할 동작

- `hub/config.py`: `hub.toml` 읽기·엄격 검증(모르는 key·hostname bind 거절), TLS 판정(`tls`/`insecure_ok`/`tls_invalid`/`insecure_http_disallowed`), 평문 경고 판정.
- `hub/web/listener.py`: Hub loop에 aiohttp `AppRunner`/`TCPSite`. 비밀번호가 없으면 열지 않음, watchdog이 `auth.json` 변화를 보면 연다, bind 실패 30 s 재시도, 정지 순서(site 정지 → WS 1001 → (확장 지점) → flush). hub_v1 `status.web` 필드.
- `hub/web/app.py`·`middleware.py`·`render.py`: Host 검사(421), Origin/Referer 검사, 세션 middleware(page `303 /login`, API 401), CSRF(상태 변경 403 `csrf_failed`), 보안 header·CSP, `html.escape` 렌더 helper와 기본 layout(평문 경고 banner, badge 자리), body 크기 상한.
- `GET/POST /login`(double-submit login token, 전역 직렬 검증, 지연, 감사), `POST /logout`.
- `tests/hub/fixtures/web_sandbox.py`: temp HOME·XDG_*·짧은 private XDG_RUNTIME_DIR·`WORKBENCH_HUB_AUTOSTART=0`, 비밀번호 설정, `127.0.0.1:0` 설정, foreground Hub 시작·정지·`/proc` 확인 helper. 이후 ticket이 공유한다.

## 수락 기준

- P2-AC-15: 비밀번호 없을 때 Hub가 어떤 TCP port도 listen하지 않음(`/proc/net/tcp*`), `wb hub status --json`의 `web.state == password_not_set`, `list`·registry 정상. `wb hub passwd --stdin` 뒤 Hub 재시작 없이 ≤ 5 s 안에 listen.
- P2-AC-16: `bind = "127.0.0.2"`면 그 주소에만 bind. TLS 파일 없음 + 기본 → HTTP. `allow_insecure_http=false` → listener 없음·`insecure_http_disallowed`. cert만 있음 → `tls_invalid`·listener 없음. Loopback 아닌 평문이면 `insecure_warning:true`와 page banner(비loopback 판정은 함수 단위 테스트로, 실제 LAN bind는 하지 않음). 자체 서명 cert·key가 있으면 HTTPS(stdlib `ssl` client, 검증 끄고 연결).
- P2-AC-17(HTTP): 로그인 cookie `HttpOnly`·`SameSite=Strict`·`Max-Age=86400`(TLS면 `Secure`), CSRF 없는 POST 403·상태 불변, 반복 실패 뒤 응답 지연 증가(시간 측정은 축소 수치 주입으로), 만료·generation 변경 세션은 `303 /login`.
- P2-AC-18: `login_success`·`login_failure`·`logout` 감사 행.
- TI-T01: 다른 Host → 421, 다른 Origin POST → 403.
- TI-T02: 모든 응답에 SPEC header·CSP, layout에 inline script 없음.

## 계약과 맥락

SPEC "`hub.toml` schema", "Web listener 수명", "인증·세션·CSRF", "보안 header". Hub SPEC (A) 확장 1. `hub/server.py`의 `Hub.status()`·`serve()`·watchdog·정지 순서. TI-02의 `PasswordStore`·`HubDb`.

## 검증

Seam T2(in-process app: middleware·로그인·header) + T3(실제 Hub: listener 개폐·bind·TLS). 독립 기대값: `/proc/net/tcp`의 bind 주소, SPEC header 문자열, cookie attribute 원문.

Behavior 순서:
1. config 검증·TLS 판정(함수).
2. 비밀번호 없음 → listener 없음·status 이유.
3. passwd 뒤 자동 개방.
4. bind 주소·port 0 기록.
5. HTTP/HTTPS·`allow_insecure_http=false`·`tls_invalid`.
6. Host 검사.
7. 보안 header·CSP.
8. 로그인 성공·cookie flag·감사.
9. 로그인 실패·지연·감사.
10. 세션 만료·generation 무효 → redirect/401.
11. CSRF·Origin 거절.
12. 정상 정지 순서(listen 해제, 프로세스 종료).

작성 범위: `src/workbench/hub/{config.py,server.py}`, `src/workbench/hub/web/{app,middleware,listener,render}.py`, `src/workbench/hub/web/pages/login.py`, `src/workbench/hub/web/static/{base.css}`, `tests/hub/fixtures/web_sandbox.py`, `tests/hub/test_hub_web_listener.py`, `tests/hub/test_hub_web_auth.py`.
