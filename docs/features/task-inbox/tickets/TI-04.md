# TI-04: inbox 저장소·상태 기계·권한·직렬화·한도

명세: [../SPEC.md](../SPEC.md) s1. 의존성·자원: SPEC "Ticket 그래프"의 TI-04. 상태·실제 assignment는 orchestrator 운영 기록에서만 관리한다.
권장 executor: Opus(`model: "opus"`). 단일 writer·도착 순서·전이 판정(ADR-0005, D-35)이 이 ticket에 모인다.

## 제공할 동작

`src/workbench/hub/inbox/{store,service,limits}.py`:
- `InboxStore(root, project_id)`: `.wb` 안전성 확인, `inbox.lock` 획득(실패 `inbox_busy`), 첫 쓰기 때 schema v1 생성(0600, WAL), `meta.project_id` 대조(`inbox_mismatch`), 읽기 전용 열기(파일 없으면 빈 결과), 60 s idle close·lock 해제.
- `InboxService`: 프로젝트별 단일 thread executor, 요청 ID → 프로젝트 index, principal(owner·board_agent·editor·requester·manager·local)별 권한 matrix, 상태 전이표 전부(SPEC "요청 상태 기계"), 편집 규칙(NEW·NEEDS_INFO 제자리, REVIEWING 제자리 + 새 review round, READY·RUNNING 새 revision + `revised` 통지 표시, CLOSED 거절), `base_version` 충돌, 댓글 kind(답변 → REVIEWING), 다시 열기, 실행 전 취소, READY·RUNNING 취소의 `cancel_state` 표시(실제 backend 호출은 port로 남김), idempotency(같은 출처·key·내용 → 기존, 다른 내용 → `idempotency_conflict`), 한도 검사(저장 전), 검토 방식 `meta.review_mode`(기본 auto), 목록·검색·badge 수·`pending_requests` 집계.
- Commit 뒤 부수 효과는 `on_committed(event)` callback(port)으로만 낸다. 통지 실패는 commit을 되돌리지 않는다.
- 모든 거절은 이유 code와 현재 `state`·`version`.

## 수락 기준

- P2-AC-01/04·23: backend 없이(프로젝트 꺼짐) 제출·조회. 프로젝트 A·B 요청이 각 `.wb/inbox.sqlite3`에만 있음(stdlib sqlite3로 확인). Hub 재시작(store 재생성) 뒤 보존.
- P2-AC-02/03: 제출이 즉시 id 반환, 중복·충돌 규칙.
- P2-AC-07: 제출은 NEW만 만든다(REVIEWING·READY 아님).
- P2-AC-20·42: 권한 matrix 전부(requester 남의 요청 `not_found`, editor 허용 전이, manager 전용 전이 거절, scope 밖 거절).
- P2-AC-29: 편집 규칙(REVIEWING 제자리 + round 증가 포함).
- P2-AC-32: 자동 삭제 API 없음, CLOSED 기본 목록 제외·filter 포함, badge 수.
- P2-AC-40: 검토 방식이 `.wb/inbox.sqlite3`에 남고 store 재생성·등록 해제/재등록 뒤 유지.
- P2-AC-43: 여러 thread가 같은 요청에 동시에 취소·편집·manager 전이를 넣을 때 적용 순서 = 제출 순서, 무효 변경은 이유와 함께 거절, 최종 state가 한 가지로 결정됨.
- P2-AC-44: 제목 201자·본문 64 KiB+1·댓글 16 KiB+1 거절, 파일 bytes 불변.
- TI-T03(일부): 다른 프로세스가 `inbox.lock`을 잡고 있으면 `inbox_busy`.
- TI-T08: `update_backup.snapshot`(Hub store 닫힌 상태)이 `inbox.sqlite3`를 committed image로 포함.

## 계약과 맥락

SPEC "요청 저장소", "요청 상태 기계", "Principal과 권한", "입력 한도". ADR-0005. `workbench.backend.paths`(`InstanceLock`, `ensure_private_dir`), `backend/project.read_project_marker`, `backend/update_backup.py`. 이 ticket은 backend 연동 port(통지·Task 취소·link)를 정의만 하고 실제 구현은 TI-09~13이 채운다.

## 검증

Seam T1. 독립 기대값: SPEC 표, 테스트가 직접 연 sqlite3 내용, 테스트가 정한 입력 순서.

Behavior 순서:
1. 없는 파일 읽기 → 빈 결과·파일 미생성.
2. 제출 → 파일·schema·권한·NEW·seq·origin.
3. idempotency 두 경우.
4. 한도 거절·불변.
5. 권한 matrix(표 기반 parameterized).
6. 전이표(허용·거절, parameterized).
7. 편집 규칙 4종 + `base_version` 충돌.
8. 답변 → REVIEWING·round.
9. 취소(실행 전) / READY·RUNNING `cancel_state`(port 호출 기록).
10. 다시 열기·link 이력 이동.
11. 직렬화·도착 순서(동시 thread).
12. `inbox.lock` 경합·`inbox_mismatch`·손상 파일 거절.
13. review_mode 저장·유지.
14. 목록·검색·badge·`pending_requests`.
15. backup 포함(TI-T08).

작성 범위: `src/workbench/hub/inbox/**`, `tests/hub/test_inbox_store.py`, `tests/hub/test_inbox_service.py`.

명령: `python3 tools/shm_tests.py -- env PYTHONDONTWRITEBYTECODE=1 PYTHONPATH=src .venv/bin/python -m unittest discover -s tests/hub -p 'test_inbox_store*.py'`, `… -p 'test_inbox_service*.py'`. 회귀: `… discover -s tests/backend/maintenance -p 'test_update_*.py'`.

독립 test_designer 검증 필수. 초점: 경합에서 순서 위반·lost update, 거절된 변경의 부분 쓰기, idempotency key의 출처 간 충돌(다른 key_id 같은 idem_key는 별개), 한도의 UTF-8 경계(다byte 문자), `.wb`가 symlink일 때 거절, 다른 프로세스가 lock을 잡은 동안 쓰기 없음, requester가 존재 여부를 알아낼 수 있는 응답 차이.
