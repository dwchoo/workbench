# TI-05: MCP Streamable HTTP endpoint·tool·2단계 cancel token

명세: [../SPEC.md](../SPEC.md) s1. 의존성·자원: SPEC "Ticket 그래프"의 TI-05(선행 TI-03, TI-04). 상태·실제 assignment는 orchestrator 운영 기록에서만 관리한다.
권장 executor: Opus(`model: "opus"`). API key 인증 경계와 외부 client 접점이다.

## 제공할 동작

`src/workbench/hub/mcp.py`와 `/mcp` route(외부 listener) + Board agent용 내부 listener 생성 함수(`127.0.0.1:0`, `/mcp`만, Host 고정; 시작은 TI-16이 부른다):
- JSON-RPC 2.0 transport(SPEC "MCP Streamable HTTP endpoint" 전부: POST 단일 객체, batch 거절, notification 202, GET 405, DELETE 204, `Accept`, `Mcp-Session-Id`, `MCP-Protocol-Version`, body 256 KiB, Origin·Host).
- Bearer API key 인증(TI-02 `verify`), 실패 401 + `WWW-Authenticate`. Cookie 무시.
- Tool 9개(`inbox_projects`, `inbox_submit`, `inbox_list`, `inbox_get`, `inbox_comment`, `inbox_update`, `inbox_set_state`, `inbox_cancel`, `inbox_result`)의 `inputSchema`·등급별 `tools/list`·`InboxService` 호출·결과/오류 mapping. `inbox_result`는 이 ticket에서 요약(`full:false`)만, `full`은 TI-14가 채운다(그 전에는 `invalid_input`이 아니라 요약 + `full_unavailable`).
- `inbox_cancel` 2단계 token: 발급·TTL 60 s·묶인 값(principal, request_id, version, task status, command_id)·1회 사용·불일치 거절. Token 확인 뒤 실제 취소는 `InboxService`의 cancel port(TI-13 전에는 테스트 가짜)로 간다.
- `tests/hub/support/mcp_client.py`: stdlib(`http.client`, `json`)만 쓰는 테스트 client(initialize → initialized → tools/list → tools/call, session id 유지).

## 수락 기준

- P2-AC-45: stdlib client가 실제 Hub에 제출·조회(get/list)·댓글·취소·결과(요약)를 호출해 성공.
- P2-AC-02/03(MCP): `inbox_submit` 즉시 반환, 중복·충돌.
- P2-AC-19: 폐기·만료 key → 401(initialize 포함). Rate limit 없음(같은 key로 200회 연속 제출 성공).
- P2-AC-20·42: requester의 `tools/list`에 편집·상태 tool 없음, 남의 요청 `not_found`, scope 밖 `forbidden`, editor 허용·거절 전이.
- P2-AC-13: 어떤 tool도 승인 명세 연결·terminal·backend 제어를 하지 않는다(tool 목록·인자 schema 정적 확인 + 호출 결과).
- P2-AC-28(MCP): 응답의 `origin`.
- P2-AC-41(token): RUNNING(가짜 상태) 첫 호출 `confirm_required`+impact, token 없음·틀림·만료·요청 version 변경·task status 변경·command 변경 → `token_mismatch`, cancel port 호출 없음. 맞는 token → port 1회 호출.
- P2-AC-44(MCP): 한도 초과 `too_large`, 저장 없음. Body 256 KiB 초과 413.
- TI-T01(MCP): 다른 Origin 403, 다른 Host 421.

## 계약과 맥락

SPEC "MCP Streamable HTTP endpoint", "Principal과 권한", "취소". MCP 2025-06-18/2025-03-26 Streamable HTTP의 message 형태(SPEC 요약을 기대값으로 쓴다). `mcp` SDK 금지(D-29).

## 검증

Seam T4(실제 Hub + stdlib client) 주, transport 세부는 T2. 독립 기대값: SPEC tool표·오류 code, JSON-RPC 2.0 규칙.

Behavior 순서:
1. 인증 없음·틀림·폐기·만료 → 401.
2. initialize·session id·version 협상.
3. 잘못된 method·batch·Accept·body 크기·Origin·Host.
4. tools/list 등급별.
5. `inbox_submit`(즉시·중복·충돌·한도).
6. `inbox_list`/`inbox_get`(requester 범위, scope).
7. `inbox_comment`(NEEDS_INFO 답변 → REVIEWING).
8. `inbox_update`/`inbox_set_state`(editor만).
9. `inbox_cancel` 실행 전 즉시, RUNNING token 2단계·불일치 6종.
10. `inbox_result` 요약.
11. 내부 listener(Board용): MCP route만, 다른 route 404, Host 고정.

작성 범위: `src/workbench/hub/mcp.py`, `src/workbench/hub/web/app.py`(route 등록), `tests/hub/support/mcp_client.py`, `tests/hub/test_hub_mcp.py`, `tests/hub/test_hub_mcp_transport.py`.

명령: `python3 tools/shm_tests.py -- env PYTHONDONTWRITEBYTECODE=1 PYTHONPATH=src .venv/bin/python -m unittest discover -s tests/hub -p 'test_hub_mcp*.py'`. 회귀: `… -p 'test_hub_web*.py'`, `-p 'test_inbox_*.py'`.

독립 test_designer 검증 필수. 초점: cookie로 `/mcp` 호출(거절), 세션 id 위조, 다른 key의 token 사용, token 재사용, JSON 깊이·큰 숫자·잘못된 UTF-8, `structuredContent`와 text의 일치, 오류가 내부 경로·stack을 노출하지 않음.
