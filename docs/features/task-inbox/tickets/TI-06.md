# TI-06: 웹 요청 page(목록·상세·작성·편집·댓글·상태·취소 확인·badge)

명세: [../SPEC.md](../SPEC.md) s1. 의존성·자원: SPEC "Ticket 그래프"의 TI-06(선행 TI-03, TI-04). 상태·실제 assignment는 orchestrator 운영 기록에서만 관리한다.
권장 executor: Sonnet(`model: "sonnet"`). 확정된 middleware·`InboxService` 위의 page 렌더링이다.

## 제공할 동작

`src/workbench/hub/web/pages/requests.py`, `static/badge.js`, `static/app.css`:
- `GET /requests`(filter: project, state, 보관함, 검색어, page), `GET /requests/new`·`POST /requests`(hidden nonce idempotency), `GET /requests/<rid>`, `GET/POST /requests/<rid>/edit`(`base_version`), `POST /requests/<rid>/comments`, `POST /requests/<rid>/state`(NEW↔NEEDS_INFO, 다시 열기), `GET/POST /requests/<rid>/cancel`(실행 전은 확인 page → 즉시 취소, READY·RUNNING은 영향 요약·token 확인 page → `InboxService` cancel port. 실제 backend 경로는 TI-13), `GET /api/badge`.
- 상세 page: 출처 label(`소유자`/`Board agent`/`key:<이름>`), 상태·outcome, revision 이력, 댓글 thread(kind별 표시), 연결 Task 자리(`task_view` 있으면 표시, 없으면 —), 결과 요약 자리, 버튼은 그 principal·상태에 허용된 것만. "검토 시작" 버튼은 TI-12가 붙인다.
- 모든 사용자 텍스트는 escape 후 `<pre>`/text. 출처·상태 label 상수는 한 곳.
- `badge.js`: 30 s마다 `/api/badge`, tab 제목 `(<pending>·<needs_info>) WB Hub`, header badge 갱신. Inline script 없음.

## 수락 기준

- P2-AC-38: 로그인 세션으로 프로젝트를 골라 작성 → 출처 소유자·NEW, 편집·댓글 반영. 새로 고침 이중 제출이 요청을 둘 만들지 않음.
- P2-AC-05: MCP로 만든 요청이 웹 상세에 같은 내용으로 보이고 웹 댓글이 MCP `inbox_get`에 보임.
- P2-AC-29(웹): 상태별 편집 결과(제자리/새 revision) 표시, 충돌 시 "다른 곳에서 바뀌었습니다" 화면과 최신 내용.
- P2-AC-31(표시): 본문 `<script>alert(1)</script>`·`<img onerror>`가 escape되어 실행 요소로 나오지 않음(HTML parse로 element 부재 확인).
- P2-AC-32: 기본 목록에 CLOSED 없음, 보관함 filter에 있음, 첨부 입력 없음, `/api/badge` 수·`badge.js` 존재.
- P2-AC-44(웹): 한도 초과 form은 이유와 함께 같은 form 재표시, 저장 없음.
- P2-AC-28(웹): 목록·상세에 출처.
- 확인 page에서 `취소` link는 상태를 바꾸지 않는다.
- TI-T02(page): 각 page 응답에 CSP header, HTML에 inline `<script>`·`on*=` 속성 없음.

## 계약과 맥락

SPEC "웹 route와 화면", "요청 상태 기계", "입력 한도". TI-03의 layout·middleware·render helper, TI-04의 `InboxService`. Hub label은 `workbench.hub.presentation`.

## 검증

Seam T2(in-process app + 실제 inbox store + 가짜 backend port). HTML 확인은 stdlib `html.parser`. 독립 기대값: SPEC route표·전이표, 테스트가 넣은 입력.

Behavior 순서: 목록(기본·filter·검색) → 작성(정상·이중 제출·한도) → 상세(출처·댓글·revision) → 편집(상태별·충돌) → 댓글(NEEDS_INFO 답변 → REVIEWING) → 상태 지정·다시 열기 → 취소 확인 page(실행 전·RUNNING token, 취소 link 불변) → escape → badge.

작성 범위: `src/workbench/hub/web/pages/requests.py`, `src/workbench/hub/web/app.py`(route), `src/workbench/hub/web/static/{badge.js,app.css}`, `tests/hub/test_web_pages_requests.py`.

명령: `python3 tools/shm_tests.py -- env PYTHONDONTWRITEBYTECODE=1 PYTHONPATH=src .venv/bin/python -m unittest discover -s tests/hub -p 'test_web_pages*.py'`. 회귀: `… -p 'test_hub_web*.py'`, `-p 'test_inbox_*.py'`.

독립 검증: test_designer가 escape(속성 문맥·URL 문맥 포함)와 권한별 버튼 노출·직접 POST 거절을 확인한다.
