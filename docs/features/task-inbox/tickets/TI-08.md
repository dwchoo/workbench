# TI-08: Hub 쪽 프로젝트 제어 실행·systemd `KillMode`/환경

명세: [../SPEC.md](../SPEC.md) s1. 의존성·자원: SPEC "Ticket 그래프"의 TI-08(선행 TI-03, **Hub HB-07**). 상태·실제 assignment는 orchestrator 운영 기록에서만 관리한다.
권장 executor: Opus(`model: "opus"`). Hub 프로세스가 backend를 띄우는 수명 경계와 웹 제어 권한 경계다.

## 제공할 동작

- `src/workbench/hub/web_control.py`: 세션 principal만 받는 `power_on`·`power_off_request`/`power_off_confirm`·`pause`·`resume`·`confirm_boot`. HB-07 `workbench.hub.projects`를 executor에서 부른다. `power_off`의 `ask`를 웹 2단계(첫 호출은 `active`와 token을 돌려주고 멈춤, 확인이 `shutdown_confirm`)로 바꾸는 adapter와 `shutdown_token_mismatch` 재요청(최대 5회 규칙은 HB-07 것을 따름). 결과 `verified`가 아니면 성공 아님. 감사 `web_control`.
- 동시 제어: 같은 프로젝트에 진행 중인 제어가 있으면 `control_in_progress`로 거절.
- `hub/service_unit.py`: unit에 `KillMode=process`와 `Environment=PATH=… SHELL=… LANG=…`(있는 것만, systemd escape)를 더한다. `wb hub status`가 옛 형식 unit(KillMode 없음)을 보면 `wb hub enable`을 다시 실행하라고 안내.
- route는 TI-12가 그린다. 이 ticket은 함수·권한·결과 형태와 최소 POST endpoint(JSON, 세션+CSRF)까지.

## 수락 기준

- P2-AC-21(동작): 세션으로 켜기 → backend `ready`·`attached:false`, 끄기 첫 단계가 `active`를 보이고 확인 전에는 아무것도 멈추지 않음, 작업 변경 → 새 목록, 확인 → `verified`. pause/resume/confirm-boot가 같은 backend 동작을 부름(HB-07 결과 그대로). API key·MCP로는 이 함수에 닿을 길이 없음(route가 세션만).
- P2-AC-20(제어): API key Bearer로 제어 endpoint 호출 → 401/403.
- TI-T06: unit 내용에 `KillMode=process`·`Environment=`(fake systemctl, S1). Hub(foreground)에서 웹으로 켠 backend가 Hub `wb hub stop`·`SIGKILL` 뒤 생존(`/proc`), backend의 ppid가 Hub가 아님.

## 계약과 맥락

SPEC "프로젝트 제어 실행", Hub SPEC "프로젝트 제어 라이브러리"·"(A) 확장 지점" 6, HB-AC-09. HB-07의 `projects.py`가 없으면 시작하지 않는다(선행 조건 미충족으로 orchestrator에 반환).

## 검증

Seam T6(실제 backend + fake OMP, Hub foreground 안에서 web_control 호출은 T2 app + 실제 backend) + T8(fake systemctl). 독립 기대값: `/proc`의 pid·ppid·session, snapshot, unit 파일 bytes.

Behavior 순서: 권한(세션만) → 켜기 → 이미 켜짐 → 끄기 1단계·거절 불변 → 작업 변경 재요청 → 확인 `verified` → pause/resume/confirm-boot → 동시 제어 거절 → unit `KillMode`·`Environment` → Hub 정지·SIGKILL 뒤 backend 생존.

작성 범위: `src/workbench/hub/web_control.py`, `src/workbench/hub/web/app.py`(최소 endpoint), `src/workbench/hub/service_unit.py`, `src/workbench/hub/cli.py`(status 안내), `tests/hub/test_web_control.py`, `tests/hub/test_hub_service.py`(갱신).

명령: `python3 tools/shm_tests.py -- env PYTHONDONTWRITEBYTECODE=1 PYTHONPATH=src .venv/bin/python -m unittest discover -s tests/hub -p 'test_web_control*.py'`, `… -p 'test_hub_service*.py'`. 회귀: `… -p 'test_project_control*.py'`.

독립 test_designer 검증 필수. 초점: token을 다른 세션·다른 프로젝트에 사용, 확인 page 취소 뒤 상태 불변, 켜기 중 Hub 정지, Hub 환경의 프로젝트 전용 변수 누출 없음(`WORKBENCH_DATA_DIR` 등), unit escape(`%`, `$`, 공백).
