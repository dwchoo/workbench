# TI-09: Hub ↔ backend 통로 계약(hub_v1 backend principal, ui_v1 비attach 3종)

명세: [../SPEC.md](../SPEC.md) s1. 의존성·자원: SPEC "Ticket 그래프"의 TI-09(선행 TI-04). 상태·실제 assignment는 orchestrator 운영 기록에서만 관리한다.
권장 executor: Opus(`model: "opus"`). 프로세스 신원과 비attach 제어 확장(보안 경계)이다.

## 제공할 동작

- `contracts/hub_v1.py`: hello의 optional `project_id`, reason `principal_mismatch`, 새 op 상수(`inbox_list`, `inbox_show`, `inbox_review`, `inbox_link_check`, `inbox_link_commit`, `inbox_delivery`, `review_mode`), docstring.
- `hub/server.py`: hello `client:"workbench-backend"`+`project_id`일 때 `SO_PEERCRED` pid와 registry 항목의 `inspect_backend` 신원(pid·start_ticks) 대조 → principal `manager(project_id)`, 아니면 `reject`/`principal_mismatch`. Backend 전용 op는 그 principal만, `review_mode`는 `local`만. 각 op는 `InboxService`로 간다(검토 결과·link의 세부 의미는 TI-10·11이 채우고, 이 ticket은 `inbox_show`/`inbox_list`와 op routing·권한까지).
- `contracts/ui_v1.py`·`backend/ui_server.py`: 새 request type `inbox_notice`, `task_status`, `cancel_task`(field 검증), `_UNATTACHED_CONTROL`에 추가(같은 `workbench-hub` 이름 + peer uid 규칙). Controller 메서드 이름 고정(`inbox_notice`, `task_status`, `cancel_task`). 이 ticket의 backend controller 구현은: `task_status`(읽기, TaskFlow·repository에서), `inbox_notice`·`cancel_task`는 `unsupported`를 돌려주는 자리(TI-10·13이 채움).
- `backend/inbox_link.py`: backend 쪽 hub_v1 client(연결 유지, 5 s 재연결, Hub 자동 시작 안 함, 호출 timeout 5 s, 결과 `ok`/`rejected`/`unavailable`/`unknown` 구분). Backend `Backend`에 붙이는 hook.
- Hub 쪽 ui_v1 호출 helper(`UiClient(name="workbench-hub")`, 신원 확인은 status.py와 같은 규칙)와 `backend_too_old` mapping.

## 수락 기준

- TI-T04: 실제 backend(fake OMP)의 `inbox_link` client는 principal을 얻는다. 테스트 프로세스가 같은 `project_id`로 hello → `principal_mismatch`. 다른 프로젝트 id로 hello → 거절. Local 연결은 backend op `unsupported`/거절.
- TI-T05: `inbox_notice`·`task_status`·`cancel_task`는 attach 없이 `workbench-hub`+같은 uid일 때만 처리, 다른 이름·uid는 `not_attached`, attach된 UI는 attach 유지, attach 자리 불변.
- `task_status`: 실제 backend에서 Task를 만든 뒤 status·revision·runs 형태(SPEC). 없는 task_id는 `exists:false`. 모델 호출·bridge frame 없음(fake OMP 기록 확인, P2-AC-06 일부).
- Hub가 없을 때 backend 시작·core 동작 영향 없음, client가 재연결.

## 계약과 맥락

SPEC "Hub ↔ backend 요청 통로". Hub SPEC "hub_v1", "ui_v1 변경: attach 없는 pause/resume"(HB-06), `hub/status.py`의 `_snapshot` 신원 규칙, `backend/process_identity.inspect_backend`.

## 검증

Seam T3b(hub_v1) + T7(UiServer + 가짜 controller) + T6(실제 backend `task_status`). 독립 기대값: `/proc`, `backend.json`, ui_v1 계약 문구.

Behavior 순서: hello project_id 형식 → principal 확인 성공 → 위조 거절 → op 권한 → `inbox_show`/`inbox_list` → ui_v1 비attach 허용·거절(3 type) → `task_status` 실물 → backend client 재연결·Hub 없음.
