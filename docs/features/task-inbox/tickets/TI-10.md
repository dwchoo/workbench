# TI-10: 검토 전달 — dispatcher·notice 결과·REVIEWING·대기 사유·검토 방식·`review-mode`·목록 요청 수

명세: [../SPEC.md](../SPEC.md) s1. 의존성·자원: SPEC "Ticket 그래프"의 TI-10(선행 TI-09). 상태·실제 assignment는 orchestrator 운영 기록에서만 관리한다.
권장 executor: Opus(`model: "opus"`). Backend → manager 주입 경로와 전달 순서·재시작 구분이다.

## 제공할 동작

- Backend: ui_v1 `inbox_notice` controller → `Watchdog.enqueue_notice(MANAGER, "inbox_request", fields)`. `MANAGER_NOTICE_TYPES`와 `bridge.ts` `NOTICE_TYPES.manager`에 `inbox_request`. `_Queued`에 최종 결과 callback(`delivered`/`unknown`/`rejected`/`dropped`), 미룬 시도의 `wait`(probe의 `editorKnown && !editorEmpty` → `manager_editor_not_empty`, 세션 없음 → `manager_session_not_connected`, pause → `paused`, 그 밖 → `manager_busy`). Snapshot additive `inbox.notices[]`. 결과는 `inbox_link` client로 hub_v1 `inbox_delivery`(Hub 없으면 메모리 보관 후 재전송).
- Hub `hub/inbox/dispatch.py`: SPEC "Hub dispatcher" 규칙(2 s + commit 직후, 프로젝트당 offered 1개, `seq` 순, 자동/수동, `revised`·`cancelled`·`linked_task_closed`는 방식 무관, delivered → REVIEWING, unknown → REVIEWING + system 댓글·재전송 없음, rejected/dropped → pending, backend 신원 변경 → 재제공 + system 댓글). 프로젝트가 꺼져 있으면 보내지 않음.
- Hub `InboxService.start_review(rid)`(웹 버튼용, owner만): 수동 pending round를 보낼 대상으로 표시(또는 unknown 뒤 "다시 전달").
- hub_v1 `review_mode`(local)와 CLI `wb hub review-mode <PATH> [auto|manual]`.
- Hub `status.py`·`presentation.py`: 행에 `pending_requests`(counts)·`review_mode`, `waits`에 snapshot inbox wait mapping과 `manager_busy` label, `요청` 열 서식. TUI·`wb hub list` 같은 label.

## 수락 기준

- P2-AC-24: 자동 + 켜진 프로젝트 + 쉬는 manager(fake OMP) → `$FAKE_NOTICES`에 `inbox_request`(event new) 1건 → 요청 REVIEWING. Worker가 Task 실행 중(fake host 명령)이어도 그 Task·명령 불변. 수동이면 통지 없음·NEW 유지, `start_review` 뒤 통지 → REVIEWING.
- P2-AC-22: fake OMP가 composer 비지 않음 상태면 통지가 미뤄지고 `wb hub list --json` 행 `waits`에 `manager_editor_not_empty`, 비우면 전달·REVIEWING·wait 해제.
- P2-AC-23: 꺼진 프로젝트에 낸 요청 3개 → 켜면 `seq` 순서대로 하나씩 통지.
- P2-AC-11·12: 결과 `unknown` → 재전송 없음·system 댓글. Backend 재시작(offered 상태) → 재제공·사유 댓글. Hub 재시작 중 delivered 보고 → 재연결 뒤 반영.
- P2-AC-07·08: 전달 ACK 전에는 REVIEWING 아님.
- P2-AC-10: 통지는 manager가 바쁠 때 보내지지 않음(probe busy → deferred).
- P2-AC-29(통지): READY·RUNNING 편집 → `revised` 통지(수동이어도). REVIEWING 편집 → 자동이면 `updated` 통지.
- P2-AC-39(일부): 수동 + 웹 `start_review`(owner만) 경로. API key principal은 거절.
- P2-AC-40: `wb hub review-mode <root> manual` → `.wb/inbox.sqlite3` meta, Hub 재시작·`remove`/`add` 뒤 유지.

## 검증

Seam T6(실제 backend + 확장 fake OMP + 실제 Hub foreground) 주, dispatcher 규칙 세부는 가짜 backend port로 T1 수준 단위 테스트. 독립 기대값: `$FAKE_NOTICES`, inbox 파일, snapshot, BRIEF 문구.

Behavior 순서: notice type 등록(bridge가 받음) → backend enqueue·결과 callback → snapshot `inbox` wait 4종 → Hub delivered → REVIEWING → 자동/수동 → `start_review` → 순서·1개 제한 → unknown·rejected·dropped → backend 재시작 재제공 → revised/updated 통지 → review-mode CLI·유지 → 목록 `pending_requests`·waits·label.

작성 범위: `src/workbench/backend/{flow_recovery,service,ui_server,inbox_link}.py`, `omp_bridge/g3/bridge.ts`(notice type), `src/workbench/hub/inbox/{dispatch,service}.py`, `src/workbench/hub/{status,presentation,cli,server}.py`, `src/workbench/backend/cli.py`(parser), `tests/recovery_boot/fake_omp.py`(확장, 기존 동작 불변), `tests/hub/test_inbox_flow_delivery.py`, `tests/hub/test_inbox_dispatch.py`, `tests/hub/test_hub_list*.py`(갱신).

명령: `python3 tools/shm_tests.py -- env PYTHONDONTWRITEBYTECODE=1 PYTHONPATH=src .venv/bin/python -m unittest discover -s tests/hub -p 'test_inbox_flow_delivery*.py'`, `… -p 'test_inbox_dispatch*.py'`, `… -p 'test_hub_list*.py'`. 회귀: `… -s tests/recovery_boot`(fake OMP 변경), `… -s tests/backend -p 'test_recovery*.py'`, `… -s tests/bridge`(bridge.ts 변경 관련).
