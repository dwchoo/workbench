# TI-12: 상태 board·프로젝트 page·제어 확인 page·검토 방식·검토 시작 버튼

명세: [../SPEC.md](../SPEC.md) s1. 의존성·자원: SPEC "Ticket 그래프"의 TI-12(선행 TI-06, TI-08, TI-10). 상태·실제 assignment는 orchestrator 운영 기록에서만 관리한다.
권장 executor: Sonnet(`model: "sonnet"`). 확정된 함수 위의 page 렌더링이다.

## 제공할 동작

- `GET /`: 상태 board 표(열·label은 `workbench.hub.presentation`), 대기 사유, 요청 수(`대기 N · 질문 M`), 검토 방식, 마지막 활동, 10 s meta refresh, 행 → `/projects/<pid>`. Hub 목록 관측이 실패한 행은 `연결 없음/불명`(꺼짐 아님).
- `GET /projects/<pid>`: 상태·Task·명령·대기 사유, 상태에 맞는 제어 버튼만(꺼짐: 켜기 / 켜짐: 끄기·일시정지 또는 재개 / 재부팅 확인 전 보류: `confirm-boot`), 검토 방식 form, 요청 link.
- `GET /projects/<pid>/<action>` 확인 page → `POST`(TI-08 `web_control`). `power-off` 확인 page는 `active` 목록과 token, mismatch면 "작업이 바뀌었습니다"와 새 확인 page. 결과 page는 `verified`일 때만 성공 문구.
- `POST /projects/<pid>/review-mode`(owner).
- 요청 상세의 "검토 시작" 버튼(수동 + pending round, 또는 delivery unknown 뒤 "다시 전달") → `InboxService.start_review`.
- 웹에 manager·worker·host pane 입력 수단이 없음을 유지(HTML에 terminal·입력 form은 `/board`뿐).

## 수락 기준

- P2-AC-21: 각 제어가 확인 page를 거침, 확인 page의 취소 link는 아무것도 바꾸지 않음(backend 상태·snapshot 불변), 끄기는 HB-AC-09 절차(목록·작업 변경 재확인).
- P2-AC-22: `manager_editor_not_empty` 행이 `manager 입력창에 작성 중인 글이 있어 알림 대기`로 보임.
- P2-AC-39(웹): 수동 프로젝트 NEW 요청에 버튼, 누르면 통지 대상(가짜 port 호출 또는 T6 실물), 자동 프로젝트·non-pending에는 버튼 없음, 직접 POST해도 거절.
- P2-AC-40(웹): 검토 방식 변경이 저장되고 page에 반영.
- 평문 경고 banner가 모든 page에 보임(insecure 상태 주입).

## 계약과 맥락

SPEC "웹 route와 화면", "프로젝트 제어 실행", "Hub 목록 연결". TI-06 layout·버튼 규칙, TI-08 `web_control`, TI-10 `start_review`·`review_mode`·waits.

## 검증

Seam T2(in-process app + 가짜 `web_control`/lister port) 주, 끄기 확인 흐름 하나는 T6 실물로. 독립 기대값: SPEC route표, Hub label 표, BRIEF 문구.

Behavior 순서: 상태 board 표·label → 관측 실패 행 → 프로젝트 page 버튼 노출 규칙 → 확인 page·취소 불변 → 각 제어 POST → 끄기 mismatch 재확인 → 검토 방식 form → 검토 시작 버튼 노출·실행·거절 → pane 입력 수단 부재.

작성 범위: `src/workbench/hub/web/pages/{board_status,projects}.py`, `src/workbench/hub/web/pages/requests.py`(버튼), `src/workbench/hub/web/app.py`(route), `tests/hub/test_web_pages_projects.py`.

명령: `python3 tools/shm_tests.py -- env PYTHONDONTWRITEBYTECODE=1 PYTHONPATH=src .venv/bin/python -m unittest discover -s tests/hub -p 'test_web_pages_projects*.py'`. 회귀: `… -p 'test_web_pages*.py'`, `-p 'test_web_control*.py'`.

독립 검증: 단위 review. test_designer는 확인 page 우회(GET으로 실행되는 경로 없음, CSRF 없는 POST 거절)만 확인한다.
