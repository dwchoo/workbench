# TI-15: OMP MCP 연결 feasibility probe

명세: [../SPEC.md](../SPEC.md) s1. 의존성·자원: SPEC "Ticket 그래프"의 TI-15. 상태·실제 assignment는 orchestrator 운영 기록에서만 관리한다.
권장 executor: Opus(`model: "opus"`). D-25("Hub MCP 하나만")의 성립 여부를 정하는 결정적 실험이다.

## 제공할 동작

결정적 가정: **이 host의 OMP(18.12.6)를 `--config` overlay와 `PI_CONFIG_DIR` 격리 home으로 띄웠을 때, Streamable HTTP MCP 서버 하나(loopback URL, `Authorization: Bearer` header)를 켜고 그 tool이 `mcp__…` 이름으로 보이며, 다른 MCP source(프로젝트 `.mcp.json`, 사용자 `~/.omp`, 다른 provider)는 보이지 않게 할 수 있다.**

가장 작은 실험(모델 호출 없음):
1. temp HOME, Board agent 형태의 격리 home(`omp_home` 규칙), `omp-isolation.yml` + probe overlay.
2. stdlib `http.server`로 만든 stub MCP 서버(loopback, initialize·tools/list·tools/call 1개, 받은 header를 기록).
3. OMP를 launcher의 isolation 관측과 같은 방식(state/tool dump, `observe_isolation`)으로 띄워 tool 목록을 얻는다. 같은 temp HOME에 미끼 MCP 설정(`~/.omp/…`, 프로젝트 `.mcp.json`, 다른 provider 위치)을 두고 그것들이 보이지 않는지 본다.
4. 찾을 것: MCP 서버를 켜는 설정 key(overlay의 `mcp.*` 또는 `mcp-json` provider + 지정 파일), `disabledProviders`에서 무엇을 빼야 하는지, header 지정 방법(값 직접 / 환경 변수 참조), tool 이름 prefix, memory·sessions 켜기 key, `--continue` 동작.

결과 판정:
- **passed**: 위 조건을 만족하는 overlay·env 구성이 있고 stub이 Bearer header를 받음 → `PROBE-OMP-MCP.md`에 정확한 구성·tool 이름 prefix·관측 출력·OMP version을 기록. TI-16은 그 구성을 쓴다.
- **failed**(HTTP MCP 불가, header 불가, 또는 단일 서버 격리 불가) → 대안 후보(Workbench 전용 OMP extension이 Hub HTTP에 붙는 Board 도구 묶음 / stdio MCP proxy)와 근거를 기록하고 orchestrator에 반환한다. SPEC 열린 결정 1로 사용자 확인이 필요하며 TI-16은 막힌다.
- **inconclusive**(dump 방식이 MCP 연결 전에 끝나는 등) → 무엇이 부족한지와 다음 최소 실험을 기록하고 반환한다.

## 수락 기준

P2-AC-33의 전제(Board agent tool 목록에 Hub MCP 외 MCP 없음)를 실험으로 확인할 방법과 결과가 문서에 있다. 실제 provider·모델·유료 호출 없음.

## 계약과 맥락

SPEC "Board agent 세트", ADR-0003 검증 요구. `omp_bridge/omp-isolation.yml:54,68`(`mcp-json` 비활성, `enableProjectConfig:false`), `backend/launcher.py`(`isolation_args`, `observe_isolation`, `isolation_leaks` `:822-857`), `backend/omp_home.py`. OMP CLI `--config`, `--no-extensions`, `-c/--continue`.

## 검증

TDD 예외(probe): 실험 script와 관측 기록이 증거다. Script는 `tests/hub/probes/omp_mcp_probe.py`(자동 테스트 suite에 넣지 않음, 수동 실행), 결과는 `docs/features/task-inbox/PROBE-OMP-MCP.md`. 실행한 OMP는 끝에 정리하고 `/proc`로 확인한다. 격리 home의 `natives` 추출 위치·용량을 기록하고, 끝나면 CLAUDE.md 용량 절차(`storage_maintenance.py` dry-run → `--apply`)를 따른다.

명령: `env PYTHONDONTWRITEBYTECODE=1 PYTHONPATH=src .venv/bin/python tests/hub/probes/omp_mcp_probe.py --report docs/features/task-inbox/PROBE-OMP-MCP.md`.

> 참고: `tests/hub/probes/omp_mcp_probe.py`는 WBX-B8(2026-10-28)에서 제거됐다. git history를 본다.

독립 검증: orchestrator가 결과 판정을 검토한다. Passed면 TI-16의 독립 test_designer가 같은 관측을 재현한다.

## 범위 밖과 중단 조건

Board agent 구현(TI-16). 사용자 실제 `~/.omp` 설정을 읽거나 바꾸지 않는다(temp HOME만, `agent.db`는 symlink를 만들되 열지 않음). 모델 호출이 필요해지면 멈추고 보고한다.
