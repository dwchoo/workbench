# TI-16: Board agent 세트 프로세스·home·overlay·격리·정지 연동

명세: [../SPEC.md](../SPEC.md) s1. 의존성·자원: SPEC "Ticket 그래프"의 TI-16(선행 TI-15 passed, TI-05, TI-02). 상태·실제 assignment는 orchestrator 운영 기록에서만 관리한다.
권장 executor: Opus(`model: "opus"`). PTY·process 수명, 설정 노출 범위(ADR-0003), Hub 정지와의 결합이다.

## 제공할 동작

- `hub/board/set.py` `BoardSet`: channel `agent`·`shell`, `pty.fork`로 각 새 session leader(Hub 자식), backend `_OwnedSession` 방식의 종료(SIGHUP → SIGTERM → 5 s → SIGKILL, 잔존 확인), 1 MiB ring buffer, resize, exit 관측(`exited`·status), restart(channel별), 첫 연결 때 lazy start, 상태 view(hub_v1 `status.board_agent`), `Hub.active()` 항목.
- `hub/board/launch.py`: Board agent home(`<hub state>/board-agent/omp-root`, `omp_home` 규칙 재사용, `agent.db` symlink), 시스템 editor key 회전(TI-02), 내부 MCP listener 시작(TI-05 함수, 127.0.0.1 임의 port), TI-15에서 확정한 overlay·env 구성 생성(key가 파일에 들어가면 0600, 시작마다 재작성), argv(`--config` isolation + overlay, `--no-extensions`, bridge extension 없음, `--append-system-prompt`, 이전 세션 있으면 `--continue`, `--model`), 시작 직후 격리 관측(Hub MCP 외 `mcp__` tool이나 isolation leak이 있으면 종료·`isolation_failed`). 환경 = `hub_environment()` + `TERM=xterm-256color`.
- `omp_bridge/board/ROLE.md`(English): SPEC의 역할·D-27 안내 두 가지·승인/전달 불가·모든 요청은 manager 검토. `hub.toml` `board_agent.role_prompt_file`은 뒤에 붙인다. `board_agent.model` 빈 값이면 `omp-models.yml` manager selector.
- `hub/server.py`: `active()`에 세트, 정상 정지 순서에 세트 종료, `SIGTERM` 경로 확인 없이 종료, 감사 `board_start`·`board_stop`·`board_restart`. `wb hub stop`·`wb update`의 확인 문구에 세트 내용(기존 `ask` 경로가 `active`를 그대로 보인다. 문구 서식만 `hub/cli.py`에서 보완).
- `POST /board/restart{channel}`(세션+CSRF, 확인 page는 TI-18) 최소 endpoint.

## 수락 기준

- P2-AC-33: (가짜 `omp`, T6b) argv에 `--no-extensions`, Workbench bridge extension 없음, isolation overlay·board overlay·role prompt, `PI_CONFIG_DIR`가 board home, `agent.db`가 사용자 store로의 symlink. Overlay가 MCP 서버 하나(내부 listener URL)만 켬. 가짜 dump가 다른 `mcp__` tool을 보이면 Board agent 종료·`isolation_failed`. Manager·worker launcher 격리 테스트 불변(회귀). (실제 OMP로) TI-15 구성의 tool 목록 재현은 독립 test_designer가 한다.
- P2-AC-33(세션 유지): 재시작 뒤 argv에 `--continue`, home의 sessions 디렉터리 유지.
- P2-AC-34(process): 세트는 WebSocket 연결과 무관하게 계속 실행(연결 없이 30 s 뒤 pid 동일), restart가 새 pid.
- P2-AC-36: ROLE.md에 GPU 확인(`nvidia-smi` 명령)·"계속할까요?"·작업 중 프로젝트 코드 수정 전 "계속할까요?"·lock 없음 문구(T9 정적).
- TI-T07: 세트가 돌 때 `stop_request.active`에 세트 항목, `wb hub stop`(`--yes` 없이 TTY 거절 → 아무것도 멈추지 않음, `--yes` → 세트 종료 뒤 Hub 정지, 세트 pid 부재). Channel 하나가 그 사이 끝나면 `stop_token_mismatch`. `SIGTERM` → 확인 없이 세트 종료. 세트가 없으면 기존처럼 묻지 않음. `wb update` 확인 목록에 세트(update fixture).
- Board agent 안에서 `wb hub status`가 관리 tree 거절 없이 동작(조상이 Hub).
