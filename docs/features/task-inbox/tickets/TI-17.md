# TI-17: WebSocket terminal 프로토콜(lease·epoch·heartbeat·인수)

명세: [../SPEC.md](../SPEC.md) s1. 의존성·자원: SPEC "Ticket 그래프"의 TI-17(선행 TI-03, TI-16). 상태·실제 assignment는 orchestrator 운영 기록에서만 관리한다.
권장 executor: Opus(`model: "opus"`). 연결 수명·인수·입력 epoch 경계다(D-28).

## 제공할 동작

`src/workbench/hub/board/ws.py`와 `GET /ws/board`:
- upgrade 전: 세션 cookie, `Origin` 정확 일치(아니면 403), API key 경로 없음.
- SPEC "WebSocket terminal 프로토콜" 전부: hello 5 s, `resume`(run·epoch) 규칙, 즉시 인수(`taken_over` → 4001), `taken_elsewhere`, binary frame(channel·epoch·payload), 현재 epoch·현재 연결 아닌 입력 버림(카운터), `resize`, `ping`/`pong`, 20 s(+1 s) 무수신 → 4002·lease `none`, `release` → 1000, EOF/RST 즉시 해제, 송신 queue 4 MiB 초과 → 4003, replay.
- Lease 상태를 `status.board_agent.lease`와 board page용 view에 반영.
- 감사 `terminal_attach`·`terminal_takeover`·`terminal_release`·`terminal_timeout`·`terminal_closed`(epoch, 이전 epoch). 입력·출력 내용은 남기지 않는다.
- Heartbeat 간격·여유는 생성자 인자(테스트 축소용). 기본 10 s / 2회.

## 수락 기준(P2-AC-35 5사례 + 동시, D-28 (6))

가짜 PTY 명령(받은 stdin을 파일에 기록, 받은 것 echo)으로 BoardSet을 띄운 실제 Hub(foreground, port 0)와 Python WebSocket client, 테스트 TCP proxy로:
1. Tab 닫기: `release` → lease `none` 즉시, `terminal_release` 감사, 세트 계속 실행.
2. Browser 강제 종료: client transport abort(close frame 없음) → ≤ 1 s 해제. Proxy가 양쪽을 멈춘 half-open → 축소 heartbeat에서 2 interval + 여유 안에 4002·`none`. 한 번은 기본 10 s로 21 s 안 해제 확인.
3. 네트워크 단절·복구: proxy blackhole → 서버 timeout → 복구 뒤 같은 client의 `resume`: (a) 그 사이 아무도 없으면 재연결(새 epoch), (b) 다른 client가 인수했으면 `taken_elsewhere`.
4. 두 tab 동시: 두 hello가 거의 동시 → 정확히 하나만 현재, 다른 하나는 `taken_over`/`taken_elsewhere`, 최종 lease epoch 하나, 이후 핑퐁 없음(자동 재연결하지 않는 client 규칙은 TI-18, 서버는 상태 일관성).
5. 인수 직후 이전 tab 입력: 새 hello 직후 이전 socket으로 보낸 binary 입력이 PTY stdin 기록에 없음.
6. 남은 "연결됨"(heartbeat 전 half-open)이 새 hello를 막지 않음.
- P2-AC-34: 다른 client(다른 cookie jar가 아니라 같은 세션의 새 연결, 그리고 다른 로그인 세션)가 인수하면 replay로 이전 출력이 보임.
- P2-AC-20·13: Bearer API key로 upgrade 시도 401, cookie 없음 401, 다른 Origin 403.
- P2-AC-18: 각 사례의 감사 행, 입력 내용 없음.

## 계약과 맥락

SPEC "WebSocket terminal 프로토콜", D-26·D-28. TI-16 `BoardSet` API, TI-03 세션·Origin middleware. aiohttp `WebSocketResponse`.

## 검증

Seam T5. 독립 기대값: D-28 6사례, 가짜 PTY stdin 기록 bytes, 감사 행, lease 상태 값.

Behavior 순서: upgrade 인증·Origin → hello·attached·replay → 입력·출력 frame → resize → ping/pong → release → EOF 해제 → heartbeat timeout → 인수(taken_over) → 이전 epoch 입력 버림 → resume 성공/taken_elsewhere → 동시 hello → 송신 queue 상한 → 감사.

작성 범위: `src/workbench/hub/board/ws.py`, `src/workbench/hub/web/app.py`(route), `src/workbench/hub/board/set.py`(lease 연결부, 필요 최소), `tests/hub/test_board_ws.py`, `tests/hub/support/tcp_proxy.py`, `tests/hub/support/ws_client.py`.

명령: `python3 tools/shm_tests.py -- env PYTHONDONTWRITEBYTECODE=1 PYTHONPATH=src .venv/bin/python -m unittest discover -s tests/hub -p 'test_board_ws*.py'`. 회귀: `… -p 'test_board_*.py'`, `-p 'test_hub_web*.py'`.

독립 test_designer 검증 필수. 초점: epoch 경계 race(인수 처리 중 도착한 입력), 32 bit epoch·run 불일치 resume, hello 전 binary frame, 큰 frame, 많은 동시 연결 시도(모두 인수 시도 → 최종 하나), slow client가 Hub loop를 막지 않음, close code별 lease 상태.
