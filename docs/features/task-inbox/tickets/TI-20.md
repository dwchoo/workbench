# TI-20: 문서(README·CONTEXT·USAGE·보안 안내)

명세: [../SPEC.md](../SPEC.md) s1. 의존성·자원: SPEC "Ticket 그래프"의 TI-20(선행 TI-19). 상태·실제 assignment는 orchestrator 운영 기록에서만 관리한다.
권장 executor: Sonnet(`model: "sonnet"`). 문서 작업이다.

## 제공할 동작

- `docs/features/task-inbox/USAGE.md`(한국어): 처음 설정(`wb hub passwd`, `hub.toml`의 `bind`·`port`·`server_names`, `wb hub tls --self-signed`, 재시작), 로그인, 요청 작성·답변·취소, 검토 방식(`wb hub review-mode`, 웹), API key 발급·등급·scope·폐기, 외부 agent의 MCP 연결 예(URL `https://<host>:<port>/mcp`, `Authorization: Bearer`, tool 목록), Board agent 세트(tab, 인수, 재시작, Hub 정지 때 확인), 결과 요약·전체 보기, 대기 사유 의미, 문제 해결(`web: not_listening` 이유별).
- 보안 안내(USAGE 안의 절): ADR-0003 결과(웹 로그인이 유일한 장벽, 평문 HTTP는 VPN 전제, Board agent·shell은 사용자 권한), API key 유출 대응, 감사 기록 위치, `0.0.0.0` 주의, `KillMode=process` 때문에 기존 `wb hub enable` 사용자는 다시 실행.
- `docs/features/workbench-hub/USAGE.md`(HB-12가 만든 경우) 또는 README의 Hub 절: `요청` 열 의미 변경, `wb hub passwd/tls/review-mode`, `status`의 web·board_agent 줄.
- `CONTEXT.md`: 필요한 용어 정리(예: "검토 round"를 쓰면 정의, "Board agent 세트" 정의에 lease·인수 언급). 기존 정의와 충돌하지 않게 최소로.
- `README.md`: Phase 2 기능 요약과 USAGE link.

## 수락 기준

명령·옵션·route·tool 이름·기본값(bind `127.0.0.1`, port 8780, `allow_insecure_http` 기본 허용, 세션 24 h, heartbeat 10 s)이 SPEC·구현과 일치한다. BRIEF의 사용자 노출 문구(대기 사유 label, 다른 곳에서 연결됨 — 다시 가져오기, 계속할까요?)를 그대로 쓴다. 대상 host 확인 항목을 "알려진 한계"로 적는다.
