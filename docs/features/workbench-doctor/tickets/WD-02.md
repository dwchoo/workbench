# WD-02: 설치본·보존·최종 독립 검증

명세: ../SPEC.md s1. Scheduling·의존성·resource·write scope·gate supplier: ../PLAN.json p1의 WD-02. 상태·실제 assignment는 Root 운영 기록에서만 관리한다.

## 제공할 동작

checkout 밖 실제 설치본과 private project/backend에서 진단 결과·원본 보존을 확인한다. independent assessment와 final review/security 통과 후 Root가 별도로 commit/push한다.

## 수락 기준·계약

WD-AC-01, WD-AC-02, WD-AC-03, WD-AC-04, WD-AC-05와 SPEC s1의 공개 seam·보존·실패 계약을 따른다. PLAN의 해당 ticket을 owner로 하는 gate 및 선행 gate를 충족한다.

## 검증

SPEC의 공개 CLI/실제 filesystem·DB/설치본 seam과 독립 sentinel·hash·process identity를 사용한다. 동작마다 RED→최소 GREEN 후 다음 동작으로 진행한다. Probe/문서의 예외는 실제 이유·대체 근거를 기록한다. Test_designer는 요구에서 먼저 도출하고 기존 coverage를 재사용하며 실제 gap만 추가한다. 동일 후보/환경의 통과 근거를 반복 실행하지 않는다. 실제 runtime을 mock 성공으로 대체하지 않는다.

 `PYTHONPATH=src python3 -m unittest discover -s tests/backend/maintenance -p 'test_doctor*.py'`; `WB_LIVE_DOCTOR=1 PYTHONPATH=src python3 -m unittest tests.integration.live_workbench_doctor`. 설치본은 기존 private wheel/uv recipe, 실제 OMP version 및 owned DB/backend fixture를 사용한다. 모델/provider/auth 검증은 하지 않는다.

## 중단·범위

사용자 데이터/auth/global 설치/실제 연구 process·유료 provider·Docker·새 도구 설치·모델 전환·중첩 위임을 사용하지 않는다. source/실행/backup 결과 불명은 Root에 근거와 함께 보고한다. 합의된 복구·보존·명시적 확인 의미를 바꾸지 않는다. 개별 leaf의 commit/push/공유 ledger/lifecycle 조작은 금지하며 Root가 최종 검증 뒤 게시한다.

## 출력

Candidate ID·변경 경로·정확한 command/result·RED 원인/당시 후보·최소 변경·GREEN·한계·소유 process 종료를 기존 result packet과 raw log에 기록한다. 상태 flag만으로 수락을 주장하지 않는다.
