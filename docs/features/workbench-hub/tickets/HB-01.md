# HB-01: Hub 프로세스·신원·hub_v1·`wb hub status/stop`

명세: [../SPEC.md](../SPEC.md) s1. 의존성·자원: SPEC "Ticket 그래프"의 HB-01. 상태·실제 assignment는 orchestrator 운영 기록에서만 관리한다.
권장 executor: Opus(`model: "opus"`). 프로세스 수명·lock·신원·새 local socket 계약이다.

## 제공할 동작

`wb _hub --foreground`로 Hub 프로세스를 직접 띄울 수 있다. Hub는 `hub.lock`으로 단일 instance를 지키고, 제어 socket을 열고, `hub.json`을 쓰고, hub_v1 `hello`/`status`/`stop_request`/`stop_confirm`에 답하며, 정상 정지·SIGTERM·watchdog으로 끝난다. `wb hub status`와 `wb hub stop`이 동작한다. 자동 시작·spawn은 HB-02다(이 ticket의 테스트는 Hub를 `_hub --foreground` subprocess로 띄운다).

## 수락 기준

- HB-T03: 두 번째 `_hub --foreground`는 lock에서 져 exit 0이고 첫 Hub는 그대로다. `hub.lock`을 지우거나 다른 inode로 바꾸면, 또는 상태 디렉터리를 지우면 Hub가 4 s 안에 끝난다. 죽은 pid의 `hub.json`이 남아 있어도 `wb hub status`는 `Hub 실행 중 아님`(exit 3).
- HB-T07: hub_v1 hello·버전 불일치 reject·1 MiB 초과 줄 reject 후 close·JSON 아님 reject·모르는 op `unsupported_type`·연결 17번째 거절·60 s idle close(정책 상수 주입으로 줄여 확인)·`stop_confirm` token 불일치/만료 거절.
- HB-AC-15(부분): Hub가 없을 때 `wb hub status`는 `Hub 실행 중 아님`, exit 3, 실행 뒤에도 Hub 프로세스 없음. `wb hub stop`도 exit 3이고 아무것도 띄우지 않는다.
- `wb hub stop`: Hub가 끝나고 lock이 풀리며 socket·`hub.json`이 지워진다. 응답 없는 Hub(테스트가 SIGSTOP)에는 같은 identity에 한해 pidfd SIGTERM을 보내고, 그래도 남으면 pid와 함께 exit 1.
- `wb hub status --json`: SPEC의 `status` 결과 필드, `unknown` 상태(lock은 잡혔지만 record 없음/불일치)면 이유와 exit 1.

## 계약과 맥락

SPEC "위치", "`hub.json` schema", "Hub 프로세스 수명"(spawn 제외), "정지 2단계", "hub_v1 제어 socket 프로토콜". `InstanceLock`(`backend/paths.py:115-212`), `write_private_json`, `unlink_stale_socket`, `process_state`(`process_identity`), `read_boot_id` 재사용. asyncio loop. 서버는 accept 때 `SO_PEERCRED` uid 확인. `HubClient`는 `hub.json` → lock holder → `process_state` → 연결 `SO_PEERCRED` → `welcome` 대조를 모두 한다. `status.web = {"state":"not_available"}`, `board_agent: null`. `stop_request.active`는 항상 `[]`이지만 함수 구조는 (A)가 항목을 더할 수 있게 둔다. `version`은 `importlib.metadata`(doctor.installation과 같은 출처), dev checkout은 `unknown`. Argparse에 `hub` group과 숨긴 `_hub`를 더한다(다른 hub 하위 명령은 뒤 ticket).

## 검증

Seam S2(실제 `_hub --foreground` 프로세스에 raw socket), S1(`wb hub status/stop` subprocess, temp HOME·`XDG_STATE_HOME`·`XDG_RUNTIME_DIR`). 독립 기대값: `/proc/locks`의 holder pid, `/proc/<pid>/stat` start ticks, SPEC 프로토콜 표.

Behavior 순서(하나씩 RED → 최소 GREEN):
1. `_hub --foreground` 시작 → `hub.json`의 pid가 `/proc/locks` holder와 같고 socket이 0600, 디렉터리 0700.
2. `hello` → `welcome.hub.pid` 일치. 버전 불일치 → `reject`.
3. `status` 결과 필드.
4. 두 번째 Hub → exit 0, 첫 Hub 유지.
5. `wb hub status`: 실행 중 / 아님(exit 3) / stale record(exit 3) / `unknown`(exit 1).
6. `stop_request` → `stop_confirm` → 프로세스 종료, lock·socket·record 정리. 잘못된 token → 거절, Hub 유지.
7. `wb hub stop` 정상 경로와 응답 없는 Hub의 SIGTERM 경로.
8. framing 한도·모르는 op·연결 상한·idle close.
9. watchdog: lock 경로 교체·상태 디렉터리 삭제 → 종료.
10. SIGTERM → 정상 정지, SIGHUP 무시.

작성 범위: `src/workbench/contracts/hub_v1.py`, `src/workbench/hub/{__init__,paths,process,server,client}.py`, `src/workbench/hub/cli.py`(status/stop), `src/workbench/backend/cli.py`(parser만), `tests/hub/test_hub_process.py`, `tests/hub/test_hub_protocol.py`. `*_independent*` 제외.

명령: `python3 tools/shm_tests.py -- env PYTHONDONTWRITEBYTECODE=1 PYTHONPATH=src .venv/bin/python -m unittest discover -s tests/hub -p 'test_hub_process*.py'`, 같은 접두사로 `-p 'test_hub_protocol*.py'`. 회귀: `… discover -s tests/backend/installation -p 'test_project_cli.py'`.

독립 test_designer 검증 필수. 초점: 단일 instance 경합(동시 `_hub` 8개), lock 파일 교체·삭제 경합, stale `hub.json`·재사용 pid로 다른 프로세스를 Hub로 오인하지 않음, `SO_PEERCRED` 대조 우회 불가, SIGTERM fallback이 identity가 다른 pid를 신호하지 않음, 정지 뒤 socket·record 잔존 없음.
