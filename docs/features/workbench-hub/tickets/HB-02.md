# HB-02: spawn·자동 시작·단일 instance·`wb hub start`

명세: [../SPEC.md](../SPEC.md) s1. 의존성·자원: SPEC "Ticket 그래프"의 HB-02. 상태·실제 assignment는 orchestrator 운영 기록에서만 관리한다.
권장 executor: Opus(`model: "opus"`). 이중 fork·session·fence·동시성 작업이다.

## 제공할 동작

`spawn_hub`가 Hub를 이중 fork + `setsid`로 띄우고 ready fd로 결과(`R`/`L`/`M`)를 받는다. `wb main()`은 argparse 뒤·handler 전에 HB-D11 규칙으로 Hub를 자동 시작하고, 실패해도 명령은 계속한다. `wb hub start`가 생긴다. 프로젝트 안의 bare `wb`는 지금처럼 start하면서 Hub도 띄운다. `WORKBENCH_HUB_AUTOSTART=0`이면 자동 시작만 꺼진다.

## 수락 기준

- HB-AC-01: Hub가 없을 때 자동 시작 대상 명령(예: `wb status`) 뒤 Hub가 있다. PTY session 안에서 `wb hub start` 후 PTY를 닫아도(SIGHUP) Hub가 남는다. 동시에 실행한 `wb hub start` 8개가 모두 같은 pid를 보고하고 Hub 프로세스는 1개다.
- HB-AC-11: 프로젝트 하위 폴더에서 bare `wb`(OMP가 없어 시작 요건 실패로 끝나도 됨) 실행 → Hub가 시작된다(자동 시작은 handler 전). 프로젝트 안 bare `wb`가 지금처럼 `start` 경로로 들어가는 것은 기존 회귀로 확인한다.
- HB-AC-15: `wb hub stop`, `wb hub status`, `wb setup --omp <없는 경로>`(실패 경로), `wb update`(개발 checkout 거절 경로), `wb doctor`, `wb --help`, argparse 오류 뒤 Hub 프로세스가 없다. (`enable`/`disable`/`passwd`/`tls`/`--version`은 HB-10.)
- HB-T04: Hub의 `/proc/<pid>/environ`에 `WORKBENCH_DATA_DIR`·`WORKBENCH_G3_*`·`WORKBENCH_AGENT_ROLES`·`WORKBENCH_OMP_RUNTIME_ROOT`가 없고, cwd가 `/`, fd 0이 `/dev/null`, fd 1·2가 `hub.log`이며 Hub의 session id가 호출자와 다르다.
- update 배타 fence를 테스트가 잡고 있으면 자동 시작은 건너뛰고(Hub 없음) 명령은 진행한다. `wb hub start`는 exit 1과 이유.
- `WORKBENCH_HUB_AUTOSTART=0`이면 자동 시작 없음, `wb hub start`는 동작.
- Hub가 비정상 종료(SIGKILL)한 뒤 다음 자동 시작 대상 명령이 새 Hub를 띄운다.

## 검증

Seam S1(CLI subprocess, temp HOME, PTY는 `pty.fork`). 독립 기대값: `/proc/locks` holder, `/proc/<pid>/stat`의 session·ppid, `/proc/<pid>/environ`·`cwd`·`fd`, BRIEF HB-D11 목록.

Behavior 순서:
1. `wb hub start` → Hub 시작, 출력 pid == lock holder, Hub session ≠ 호출자 session.
2. 이미 실행 중이면 같은 pid, 새 프로세스 없음.
3. 동시 8개 → Hub 1개.
4. PTY 닫기 뒤 생존.
5. 자동 시작: `wb status`(실행 중 아님 경로) 뒤 Hub 있음.
6. 예외 명령마다 Hub 없음(표를 데이터로 순회).
7. update fence 보유 중 → 자동 시작 건너뜀, `wb hub start` exit 1.
8. 환경·cwd·fd 정리(HB-T04).
9. opt-out env.
10. SIGKILL 뒤 재시작.
11. 상태 디렉터리 소멸·교체 → Hub 자체 종료(SPEC "열린 결정" orchestrator 확정의 안전장치: temp HOME 삭제 뒤 Hub가 남지 않음).

작성 범위: `src/workbench/hub/process.py`, `src/workbench/hub/cli.py`(start), `src/workbench/backend/cli.py`(`main`, parser), `tests/hub/test_hub_spawn.py`, 위 공용 test env helper(env 한 줄만).

명령: `python3 tools/shm_tests.py -- env PYTHONDONTWRITEBYTECODE=1 PYTHONPATH=src .venv/bin/python -m unittest discover -s tests/hub -p 'test_hub_spawn*.py'`. 회귀: `… discover -s tests/hub -p 'test_hub_process*.py'`, `… discover -s tests/backend/installation -p 'test_project_cli.py'`, `… discover -s tests/backend/maintenance`.

독립 test_designer 검증 필수. 초점: 동시 spawn 경합과 `L` 처리, 중간 프로세스 zombie 없음, ready fd 시간 초과·EOF 처리, Hub가 호출자 fd(특히 terminal·pipe)를 물려받지 않음(호출자 `subprocess.run(capture_output=True)`가 Hub 때문에 끝나지 않는 일이 없음), 예외 명령 누락, fence 경합.

## 범위 밖과 중단 조건
