# HB-03: WB 관리 process tree 안 자동 시작 보류

명세: [../SPEC.md](../SPEC.md) s1. 의존성·자원: SPEC "Ticket 그래프"의 HB-03. 상태·실제 assignment는 orchestrator 운영 기록에서만 관리한다.
권장 executor: Opus(`model: "opus"`). subreaper 재부모화·프로세스 신원 경계다.

## 제공할 동작

Hub가 어느 WB 프로젝트의 backend·supervisor 후손이 되지 않게 한다. 호출자 사전 확인(자동 시작·`wb hub start`)과 exec된 Hub의 재부모화 뒤 자기 확인(lock 전)을 같은 판정 함수 `managed_ancestor`로 한다.

## 수락 기준

- HB-T01: argv에 `_backend`·`workbench` 원소가 있는 가짜 조상 아래에서 자동 시작 대상 `wb` → Hub 없음, 명령은 계속, stderr가 TTY면 안내 한 줄(TTY가 아니면 없음). `wb hub start` → 같은 문구, exit 2, Hub 없음.
- `PR_SET_CHILD_SUBREAPER`를 켠 `… shell_g2/lifecycle.py --supervisor …` 모양 조상 아래에서도 같다.
- 사전 확인을 우회해 `spawn_hub`를 같은 조상 아래에서 직접 부르면(테스트용 driver) Hub가 lock을 잡기 전에 exit 3, ready `M`, 조상 subreaper에 남은 프로세스 없음, `hub.lock` 미보유.
- 관리 tree 밖(일반 조상 + subreaper인 일반 프로세스)에서는 정상 시작한다(과잉 거절 없음).
- 이미 Hub가 실행 중이면 관리 tree 안의 `wb hub list`류도 그 Hub를 쓴다(HB-05 이후 확인, 이 ticket에서는 `wb hub status`로 확인).
- `/proc` 읽기 실패(주입)는 "안"으로 본다.

## 계약과 맥락

SPEC "WB 관리 process tree와 자동 시작 보류". 판정 기준은 `maintenance.discover()`의 `_backend` 기준과 supervisor argv 모양(`terminal/shell_g2/lifecycle.py:818-821`). supervisor의 수명 대기(`lifecycle.py:780` 이후), 종료 시 `left_session` 표시(`service.py:1396-1418`), `wb update`의 `left_session` 거절(`update.py:251-253`)이 이 ticket이 막는 결과다.

## 검증

Seam S9(관리 tree fixture) + S1. Fixture: 테스트가 `python -c` 프로세스를 argv `[..., "_backend", "--data-dir", "/x/workbench-fixture"]` 모양(`sys.argv` 조작이 아니라 exec argv)으로 띄우고 그 자식으로 `wb`를 실행. Subreaper fixture는 `prctl(PR_SET_CHILD_SUBREAPER)` 후 argv 끝이 `shell_g2/lifecycle.py`인 경로 + `--supervisor`로 exec한 helper. 독립 기대값: fixture pid, `/proc/<hub>/stat`의 ppid, `/proc/locks`.

Behavior 순서:
1. `managed_ancestor`가 backend 모양 조상을 찾는다(직접 함수 호출 + `/proc`).
2. supervisor 모양 조상.
3. 일반 조상은 찾지 않는다.
4. 자동 시작 보류 + TTY 안내 / 비TTY 무음.
5. `wb hub start` exit 2.
6. 자기 확인: driver가 사전 확인 없이 spawn → exit 3·`M`·lock 미보유·남은 프로세스 없음.
7. `/proc` 실패 주입 → 안.

작성 범위: `src/workbench/hub/process.py`, `src/workbench/hub/server.py`(자기 확인), `tests/hub/test_hub_managed_tree.py`, `tests/hub/fixtures/`(fixture helper).

명령: `python3 tools/shm_tests.py -- env PYTHONDONTWRITEBYTECODE=1 PYTHONPATH=src .venv/bin/python -m unittest discover -s tests/hub -p 'test_hub_managed*.py'`. 회귀: `… -p 'test_hub_spawn*.py'`, `… -p 'test_hub_process*.py'`.

독립 test_designer 검증 필수. 초점: 재부모화 타이밍(중간 프로세스가 늦게 끝남), 조상 체인 중간 프로세스 소멸 경합, argv 모양 변형(인터프리터 경로·`-I`·`-c`), subreaper 아래 남는 zombie·고아, 과잉 거절.

## 범위 밖과 중단 조건

실제 실험 run 안에서의 확인은 HB-11. 다른 프로젝트 backend가 supervisor로 재부모화되는 기존 위험(SPEC "범위 밖 위험")은 고치지 않는다. Hub를 tree 밖으로 탈출시키는 다른 기제(systemd-run 등)를 들이지 않는다(필요하면 멈추고 보고).
