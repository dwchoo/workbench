# HB-06: ui_v1 attach 없는 `pause`/`resume`

명세: [../SPEC.md](../SPEC.md) s1. 의존성·자원: SPEC "Ticket 그래프"의 HB-06. 상태·실제 assignment는 orchestrator 운영 기록에서만 관리한다.
권장 executor: Opus(`model: "opus"`). backend 공개 계약(ui_v1) 변경이다.

## 제공할 동작

UiServer가 `pause`/`resume`을 attach하지 않은 연결에서도 받는다. 조건: hello `client`가 `ui_v1.NON_ATTACHED_CONTROL_CLIENTS`(`{"workbench-hub"}`)에 있고, accept 때 기록한 그 연결의 `SO_PEERCRED` uid가 backend euid와 같다. 나머지는 지금처럼 `not_attached`. attach 자리를 차지하지 않고, 성공 뒤 attach된 UI에 `state`를 push한다. ui_v1 docstring을 고친다.

## 수락 기준

- HB-T02: attach된 UI가 있는 상태에서 별도 연결(`workbench-hub`, 비attach)의 `pause` → `ok`, controller `pause` 1회, attach된 UI는 attach 상태 유지·`state` push 수신. `resume{reconciled:true}` 같음, `reconciled:false` → `resume_not_reconciled`.
- 다른 client 이름(`workbench-cli`, `workbench-ui` 등)의 비attach `pause` → `not_attached`, controller 미호출.
- peer uid 불일치(주입) → `not_attached`.
- 그 뒤 새 UI의 `attach`가 성공한다(Hub 요청이 attach 자리를 쓰지 않음). attach된 UI가 없을 때도 비attach `pause` 성공.
- 기존 동작 불변: attach된 연결의 `pause`/`resume`, 다른 attach 필요 요청(`input`, `stop_command` 등)은 비attach `workbench-hub`에게도 `not_attached`.
- `snapshot`·`shutdown_*`·`confirm_boot`의 기존 비attach 허용 불변.

## 계약과 맥락

SPEC "ui_v1 변경: attach 없는 `pause`/`resume`". `ui_server.py`의 `_dispatch`(`:344-414`), `_require_attached`(`:340`), `_Connection`(`:68`), 요청 뒤 push 로직(`_handle` 끝부분)과 `push_state`(`:266`). `contracts/ui_v1.py` docstring의 `pause`/`resume` 절(`:218-224`)과 상수. 실제 backend 쪽 `Backend.pause/resume`(`service.py:2249-2255`)은 바꾸지 않는다. Peer 신원 읽기는 `UiServer`의 작은 메서드로 두어 테스트 하위 클래스가 덮어쓸 수 있게 한다(S5의 주입점). ui_v1 `VERSION`은 올리지 않는다.

## 검증

Seam S5(실제 `UiServer` + 가짜 controller, `tests/backend/test_ui_server.py` 패턴의 실제 UDS 연결). 계약 문구는 `tests/contracts/test_ui_v1.py`. 독립 기대값: ui_v1 계약 문구(이 SPEC), controller 호출 기록.

Behavior 순서:
1. 비attach `workbench-hub` `pause` → ok.
2. 다른 이름 → `not_attached`.
3. uid 불일치 주입 → `not_attached`.
4. attach된 UI 유지·push 수신.
5. `resume` reconciled 규칙.
6. 이후 새 attach 성공, attach 필요 다른 요청은 계속 거절.
7. docstring·상수 정적 확인(TDD 예외, 문구).

작성 범위: `src/workbench/backend/ui_server.py`, `src/workbench/contracts/ui_v1.py`, `tests/backend/test_ui_server_hub_control.py`, `tests/contracts/test_ui_v1.py`(상수·문구 확인 추가).

명령: `python3 tools/shm_tests.py -- env PYTHONDONTWRITEBYTECODE=1 PYTHONPATH=src .venv/bin/python -m unittest discover -s tests/backend -p 'test_ui_server_hub_control*.py'`, `… -m unittest tests.contracts.test_ui_v1`. 회귀: `… discover -s tests/backend -p 'test_ui_server*.py'`, `… discover -s tests/contracts`, `… discover -s tests/backend -p 'test_cw18_*.py'`.

독립 test_designer 검증 필수, security review trigger(제어 경계 확장). 초점: client 이름 위조로 다른 attach 필요 요청이 열리지 않음, hello 전·버전 불일치 연결의 우회 없음, 동시 attach UI의 pause와 Hub pause 겹침, attach된 연결이 끊긴 직후의 비attach 요청.

## 범위 밖과 중단 조건

Hub 쪽 호출 라이브러리(HB-07), 새 request type, automation 동작 변경. `pause`/`resume`의 의미·결과 필드를 바꾸지 않는다. 다른 요청의 attach 규칙을 바꾸지 않는다(바꿔야 하면 멈추고 보고).
