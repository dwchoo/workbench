# HB-08: TUI Hub 목록·bare `wb` 밖 분기

명세: [../SPEC.md](../SPEC.md) s1. 의존성·자원: SPEC "Ticket 그래프"의 HB-08. 상태·실제 assignment는 orchestrator 운영 기록에서만 관리한다.
권장 executor: Sonnet(`model: "sonnet"`). 기존 product UI의 model/view 분리를 따르는 UI 작업이다.

## 제공할 동작

프로젝트 밖의 bare `wb`가 curses Hub 목록을 띄운다. 목록은 Hub `list`를 3 s마다 받아 SPEC 열로 그린다. 켜진 행 `Enter` → `run_product`로 진입, detach → 목록 복귀. 꺼진 행 `Enter` → "켤까요?" → `y`만 켜고 진입. `o` 켜기, `x` 끄기, `r` 새로 고침, `q` 종료. TTY가 아니면 exit 2와 `wb hub list` 안내.

## 수락 기준

- HB-AC-10(model): `on` 행 `Enter` → `Attach(entry)` action. App: `run_product` 반환 0·1 → 목록으로 돌아와 notice, 2 → exit 2.
- HB-AC-16(model): `off` 행 `Enter` → modal `"<이름>"을(를) 켤까요? [y/N]`. `y` → `PowerOn(attach=True)`. `n`·`Esc`·`Enter`·그 밖의 key → action 없음, modal 닫힘, 같은 행 선택 유지.
- HB-AC-13(model): `mismatch`·`unknown` 행의 `Enter`·`o`·`x` → action 없음, 이유 notice. `starting`·`closing` → notice만.
- HB-AC-09(model): `on` 행 `x` → `PowerOff(entry)`. `off`에서 `x`, `on`에서 `o`는 action 없음.
- HB-AC-12·19(model/presentation): 열 순서와 label이 `wb hub list`와 같다(같은 `presentation`), `pending_requests` `—`.
- Hub 연결 끊김 → 상단 "Hub 연결 없음", 모든 행 상태를 `연결 없음/불명`으로 표시(행은 유지).
- 빈 목록 → 안내 문구.
- bare `wb`: 프로젝트 안이면 기존 start(회귀), 밖 + TTY → 목록, 밖 + 비TTY → exit 2.

## 계약과 맥락

SPEC "TUI Hub 목록", "상태 집계"의 label 표, "CLI 계약" bare `wb`. `ui/product/{model,view,app}.py`의 분리 방식과 `run_product`(`ui/product/app.py:235-303`: TTY 확인, termios 복구, detach 문구). App은 curses를 끝낸 상태에서 `Attach`(실행 직전 `inspect_backend`로 identity 재확인)·`PowerOn`(`projects.power_on` 출력 그대로, 실패 시 "Enter를 누르면 목록으로")·`PowerOff`(`projects.power_off`를 terminal 문답으로) 를 실행하고 다시 curses로 들어간다. `main()`의 bare 분기는 `values`가 비었을 때만 적용한다(명시 `wb start`는 그대로). Hub가 필요하므로 자동 시작 실패·관리 tree 거절이면 exit 1/2.

## 검증

Seam S7(model 순수 단위 + presentation). App·view는 S8 PTY e2e로 HB-11에서 확인한다(view에는 별도 RED 없음, SPEC TDD 예외). 독립 기대값: BRIEF HB-AC-10·13·16 문장, SPEC label 표, 테스트가 준 행.

Behavior 순서:
1. 행 목록·선택 이동(경계 포함).
2. `on` `Enter` → `Attach`.
3. `off` `Enter` → modal, `y` → `PowerOn(attach=True)`.
4. modal에서 그 밖의 key → 없음.
5. `o`·`x` 허용 상태.
6. `mismatch`·`unknown`·`starting`·`closing` 거절 notice.
7. Hub 연결 끊김 표시.
8. 열 서식·`—`.
9. bare `wb` 분기(S1 subprocess: 밖 + 비TTY exit 2, 안은 기존 경로).

작성 범위: `src/workbench/ui/hub_list/{__init__,model,view,app}.py`, `src/workbench/backend/cli.py`(`main` bare 분기), `tests/ui/test_hub_list_model.py`, `tests/hub/test_hub_cli_bare.py`.

명령: `python3 tools/shm_tests.py -- env PYTHONDONTWRITEBYTECODE=1 PYTHONPATH=src .venv/bin/python -m unittest discover -s tests/ui -p 'test_hub_list_model*.py'`, `… discover -s tests/hub -p 'test_hub_cli_bare*.py'`. 회귀: `… discover -s tests/ui -p 'test_product_entrypoint.py'`, `… discover -s tests/backend/installation -p 'test_project_cli.py'`.

독립 test_designer 검증 권장. 초점: modal 중 polling 갱신으로 선택 행이 바뀌어도 다른 프로젝트를 켜지 않음(modal은 확인 시점 entry root로 결속), 목록 갱신 중 사라진 행, 좁은 terminal 서식.

## 범위 밖과 중단 조건

웹(A), pause/resume·confirm-boot의 TUI 노출(BRIEF 범위 밖). `run_product`·product UI를 바꾸지 않는다(필요하면 멈추고 보고). 켜기·끄기 절차를 이 ticket에서 다시 구현하지 않는다(HB-07 라이브러리만 호출).
