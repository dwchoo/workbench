# HB-09: `wb update`의 Hub 정지

명세: [../SPEC.md](../SPEC.md) s1. 의존성·자원: SPEC "Ticket 그래프"의 HB-09. 상태·실제 assignment는 orchestrator 운영 기록에서만 관리한다.
권장 executor: Opus(`model: "opus"`). update fence·backend 종료 순서·Hub 수명이 얽힌다.

## 제공할 동작

`wb update`가 `refuse_managed_caller` 뒤, 백엔드 종료 전에 `stop_hub`로 Hub를 멈춘다. Hub 정지 사실을 확인 목록에 더하고(Hub만으로 새 문답을 만들지 않음), 실패하거나 Hub가 `unknown`이면 어떤 backend도 종료하지 않고 중단한다. 업데이트 뒤 Hub를 다시 띄우지 않는다.

## 수락 기준

- HB-AC-18: update fixture(`tests/backend/maintenance/test_update_cli.py`의 `InstalledFixture`)에서 실제 Hub(`_hub --foreground`, 같은 temp HOME)가 실행 중일 때 `wb update` → 설치 명령 double이 불릴 때 Hub 프로세스가 이미 없다(double이 `/proc/locks`로 확인해 기록). 출력에 `Hub(pid N…)를 멈춥니다`.
- 진행 중 작업이 없으면 지금처럼 묻지 않고 진행한다(Hub만으로 문답 없음).
- Hub가 응답하지 않고 SIGTERM에도 남으면(테스트가 SIGTERM을 무시하는 가짜 Hub로 주입) exit 1, backend shutdown 미호출, 설치 미호출, 안내에 `wb hub stop`.
- Hub `unknown`(lock은 잡혔는데 record 없음) → 같은 중단.
- 업데이트 완료 뒤 Hub 프로세스 없음(`wb update`는 예외 명령이며 Hub를 띄우지 않음).
- HB-T06: Hub 실행 중 `maintenance.discover()`가 오류 없이 backend 목록만 돌려주고(Hub를 backend로 보지 않음, `omp-workbench/` runtime base에 Hub 디렉터리 없음), `require_no_writers(<project .wb>)`가 Hub 때문에 실패하지 않는다.
- update 진행 중(배타 fence)에는 다른 `wb`의 자동 시작이 Hub를 띄우지 않는다(HB-02 동작의 update 맥락 확인).

## 계약과 맥락

SPEC "`wb update`와의 관계", "정지 2단계". `update._run`(`backend/update.py:231-` ), `refuse_managed_caller`(`:193-228`), `discover`·`require_no_writers`(`maintenance.py`). HB-01의 `stop_hub`·`HubIdentity`를 쓴다. `stop_request.active`가 비어 있지 않은 경우((A))의 문답 통합 자리를 함수 구조로 남긴다(지금은 항상 빈 목록).

## 검증

Seam S1(update fixture, in-process `cli.main(['update'])` 패턴 + 실제 Hub subprocess). 독립 기대값: `/proc/locks` holder, double이 기록한 호출 순서, 파일 존재.

Behavior 순서:
1. Hub 없음 → 기존 update 경로 그대로(회귀).
2. Hub 실행 중 → 설치 전 정지, 문구.
3. 작업 없음 → 문답 없음.
4. 정지 실패 → backend·설치 미호출, exit 1.
5. `unknown` → 같은 중단.
6. 업데이트 뒤 Hub 없음.
7. `discover()`·`require_no_writers` 불간섭.

작성 범위: `src/workbench/backend/update.py`, `tests/backend/maintenance/test_update_hub.py`.

명령: `python3 tools/shm_tests.py -- env PYTHONDONTWRITEBYTECODE=1 PYTHONPATH=src .venv/bin/python -m unittest discover -s tests/backend/maintenance -p 'test_update_hub*.py'`. 회귀: `… discover -s tests/backend/maintenance -p 'test_update_*.py'`, `… -p 'test_doctor*.py'`.

독립 test_designer 검증 필수. 초점: 정지와 backend 종료의 순서, 정지 실패 시 상태 무변경(백업 디렉터리·`update-resume.json` 미생성), Hub 정지 직후 새 Hub가 끼어들지 못함(fence), Hub record와 다른 pid를 신호하지 않음.
