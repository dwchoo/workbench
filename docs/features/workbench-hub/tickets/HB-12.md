# HB-12: 문서(README·CONTEXT·USAGE)

명세: [../SPEC.md](../SPEC.md) s1. 의존성·자원: SPEC "Ticket 그래프"의 HB-12. 상태·실제 assignment는 orchestrator 운영 기록에서만 관리한다.
권장 executor: Sonnet(`model: "sonnet"`). 문서 작업이다.

## 제공할 동작

HB-11에서 검증된 동작을 사용자 문서에 반영한다.

## 수락 기준

- `docs/features/workbench-hub/USAGE.md`(새 문서, `docs/features/workbench-update/USAGE.md`의 형식을 따름): bare `wb` 안/밖, TUI 목록 key, 켜기·끄기, `wb init`, `wb hub start|stop|status|list|add|remove|enable|disable`, 자동 시작 예외 명령, WB 관리 terminal 안의 자동 시작 보류와 안내, `wb update`와 Hub, linger 설명, Hub 위치(상태·log·socket), "연결 없음/불명"의 뜻.
- `README.md`: Hub 절 추가(짧게, USAGE 링크). 프로젝트 밖 bare `wb`가 목록이 된 변화와 새 프로젝트 만들기(`wb init`/`wb start`)를 적는다.
- `CONTEXT.md`: 기존 Hub·Hub 등록·WB 프로젝트 켜기/끄기 항목이 실제 동작과 맞는지 확인하고, 필요하면 "Hub 목록"·"WB 관리 terminal" 같은 용어만 더한다(정의 중복 없이). 용어 변경은 최소로 한다.
- `WORKBENCH_HUB_AUTOSTART`를 사용자 문서에 적을지는 SPEC "열린 결정" 4의 사용자 답을 따른다(답이 없으면 개발 문서에만 적는다).
- 설치 문서(WI-AC-05·13 문구)의 갱신 여부는 SPEC "열린 결정" 5의 답을 따른다.

## 계약과 맥락

SPEC 전체, HB-11 `VERIFICATION.md`. AGENTS.md 문서 규칙(한국어, 식별자 원문). 명령 이름·문구는 실제 `wb --help`·`wb hub --help` 출력과 대조한다.

## 검증

TDD 예외(문서). 정적 확인: 문서에 나온 모든 `wb …` 명령이 `wb --help`/`wb hub --help`에 있고, 문구가 SPEC·실제 출력과 맞는다(명령으로 대조한 결과를 보고). 링크가 깨지지 않는다.

작성 범위: `README.md`, `CONTEXT.md`, `docs/features/workbench-hub/USAGE.md`.
