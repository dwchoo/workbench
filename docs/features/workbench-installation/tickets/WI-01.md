# WI-01: OMP 배포 방식과 SDK 호환의 최소 판별

Specification: [SPEC.md s1](../SPEC.md). Scheduling: [PLAN.json p1](../PLAN.json)의 `WI-01` 항목이 유일한 dependency/resource 원본이다.

## 제공 동작

기존 OMP 재사용 경로와 새 stable 설치 후보를 사용자 HOME과 분리된 임시 경로에서 비교한다. 실행 파일의 --version 성공과 실제 entry.ts의 SDK import/등록 성공을 구분한다. 기존 검증 probe를 재사용하되 현재 버전과 경로의 근거를 새로 남긴다.

산출물: 현재 stable 배포의 실행 파일·실제 bridge SDK 로드·scripted child 세션을 판별한 배포 recipe 및 실패 분류.

미설치/기존 설치/고장난 실행 파일의 fixture 분류는 behavior별 RED → 최소 GREEN. 다운로드·배포 feasibility 자체는 probe 예외이며 passed/failed/inconclusive와 원문 원인을 기록한다. 실제 extension 등록, SDK의 bundled task 정의 접근, loopback scripted provider의 제한된 child 세션 1회와 Python writer 귀환을 관측한다. 외부 유료 모델·사용자 인증·연구 실험은 사용하지 않는다. G-WI-01은 wheel 통합 성공을 주장하지 않는다.

소유 gate: G-WI-01. required evidence level·supplier는 PLAN gate 항목을 따른다. 소유 gate는 자신의 산출물과 transitive predecessors만 요구하며 이후 통합 G-WI-10/11을 앞 ticket의 완료 조건으로 역참조하지 않는다.

## 제외 범위와 중단 조건

binary와 Bun 후보 모두 현재 stable에서 공개 SDK 경계를 만족하지 못하면 affected WI-02/WI-04 확대를 멈추고 같은 issue에 원인·다음 판별을 기록한다. 단순 timeout을 비호환으로 확정하지 않는다. sudo·기존 설치 교체·SDK private API·별도 Python agent는 범위 밖이다.

새 제품 결정·test seam 변경·승인 범위 밖 의존성이 필요하면 Root에 근거와 영향 ticket/gate를 전달한다. leaf는 workflow 재진입·추가 위임하지 않는다.
