# WI-02: 개발 checkout 없이 동작하는 WB 패키지와 자산

Specification: [SPEC.md s1](../SPEC.md). Scheduling: [PLAN.json p1](../PLAN.json)의 `WI-02` 항목이 유일한 dependency/resource 원본이다.
상태: bundle 승인 대기인 계획 초안. 실행 상태·writer·후보·검증은 Root의 `.workflow/workbench-installation/` 기록에서 관리한다.

## 제공 동작

Git source의 noneditable uv tool 설치본이 checkout 밖 프로젝트에서 --help를 실행하고 bridge·models·isolation overlay·agents·skills/reference/helper·policy를 읽는다. WB report의 Manager user-only 노출과 Worker 미노출을 보존한다.

산출물: wheel/sdist에 필요한 자산 전체를 포함하고 설치본 경로로 실행하는 wb/omp-workbench entry points.

## 수락 기준

WI-AC-01, WI-AC-02, WI-AC-10. [SPEC의 전체 acceptance trace](../SPEC.md#수락-기준)의 해당 행을 적용하며 생략하지 않는다.
이 ticket의 local 관측과 후속 integration 관측을 구분한다. 완료 표시만으로 사용자 수락을 충족하지 않는다.

## 계약과 관련 맥락

WI-01의 통합된 recipe/자산 closure를 소비한다. Python package resources를 단일 resolver로 사용하고 build 시 canonical omp_bridge 자료를 package asset으로 수집한다. Python module/JSON policy와 TS 상대 import, fixed summary writer, shell helper, summary compatibility 검증 자산을 함께 다룬다. .agents/.codex 개발 skills를 제품에 포함하지 않는다. project 복사는 금지한다.

BRIEF r0.4의 WI-D01~10은 개별 사용자 결정이다. WI-P01/P03~07와 SPEC의 기술·test seam 제안은 전체 bundle 확인 대기이며 이 ticket 파일의 존재가 승인은 아니다.
구체 write 범위는 PLAN의 `write_scope_hint`를 출발점으로 Root가 dispatch 직전 실제 base/dirty files와 대조한다. 기존 사용자 변경을 보존한다.

## 검증

package artifact를 설치한 임시 tool 환경의 subprocess 공개 seam으로 RED → 최소 GREEN. checkout을 참조할 수 없는 cwd, PYTHONPATH 제거, read-only 설치 자산, Python namespace/data JSON, report reference/helper 실행을 검증한다. 자산 expected 목록은 SPEC의 분류와 canonical 파일 hash에서 독립적으로 만들고 구현 resolver 반환을 정답으로 복제하지 않는다. G-WI-02는 새 project CLI 동작 대신 설치·자산 경계만 판정한다.

소유 gate: G-WI-02. required evidence level·supplier는 PLAN gate 항목을 따른다. 소유 gate는 자신의 산출물과 transitive predecessors만 요구하며 이후 통합 G-WI-10/11을 앞 ticket의 완료 조건으로 역참조하지 않는다.

예정 명령(이 planning에서는 실행하지 않음; 새 경로는 이 ticket 또는 명시된 prerequisite가 작성):

```sh
PYTHONPATH=src:. python3 -m unittest discover -s tests/backend/installation -p 'test_package_assets.py' -v
```

일반 behavior는 Root가 실제 `.agents/skills/tdd/SKILL.md` identity와 승인된 SPEC test seam을 packet에 넣어 한 행동의 RED → 최소 GREEN → 다음 행동 순서로 수행한다.
RED의 원인·당시 후보/명령, 최소 production delta, GREEN 후보/명령을 남긴다. unrelated import/도구 오류를 의미 있는 RED로 주장하지 않는다.
독립 test_designer는 worker 구현을 정답으로 복제하지 않고 승인된 요구·독립 expected values에서 검증을 평가/보완한다. coherence unit의 fresh general review와 최종 feature의 Standards/Spec pair, 해당 security review는 Root가 계약 §7에 따라 수행한다.

## 제외 범위와 중단 조건

해결되지 않은 SDK 공급이나 상대 경로가 남으면 성공 처리하지 않는다. summary compatibility 보호를 disable하거나 hash 검증을 항상 성공으로 바꾸지 않는다. 전체 architecture 리팩터링과 PyPI 게시는 제외한다.

새 제품 결정·test seam 변경·승인 범위 밖 의존성이 필요하면 Root에 근거와 영향 ticket/gate를 전달한다. leaf는 workflow 재진입·추가 위임하지 않는다.
