# WI-03: 프로젝트 식별과 영속 상태·runtime 경로 계약

Specification: [SPEC.md s1](../SPEC.md). Scheduling: [PLAN.json p1](../PLAN.json)의 `WI-03` 항목이 유일한 dependency/resource 원본이다.
상태: bundle 승인 대기인 계획 초안. 실행 상태·writer·후보·검증은 Root의 `.workflow/workbench-installation/` 기록에서 관리한다.

## 제공 동작

명시 data-dir > 환경 변수 > 현재·상위 .wb 순으로 context를 구한다. 초기화는 folder 표시와 확인 뒤에만 수행하고 non-TTY/거절에는 생성하지 않는다. status/attach/shutdown 조회는 초기화하지 않는다. 일반 Git·Git worktree·비Git 폴더, 하위 폴더·긴 경로·동시 초기화·잘못된 marker를 다룬다.

산출물: 확인 후 .wb 초기화, 상위 탐색, 충돌 거절, Git 제외, 짧은 외부 runtime의 공개 context/layout API.

## 수락 기준

WI-AC-03, WI-AC-05, WI-AC-06, WI-AC-10, WI-AC-11, WI-AC-15. [SPEC의 전체 acceptance trace](../SPEC.md#수락-기준)의 해당 행을 적용하며 생략하지 않는다.
이 ticket의 local 관측과 후속 integration 관측을 구분한다. 완료 표시만으로 사용자 수락을 충족하지 않는다.

## 계약과 관련 맥락

SPEC §프로젝트와 경로의 proposed ProjectContext/durable/runtime layout을 고정한다. 이 ticket은 public Python context/layout seam을 완성하며 CLI와 실제 backend 연결은 WI-05 소유다. 기존 DataLayout(root) 사용과 explicit legacy data-dir은 읽을 수 있어야 하고 legacy runtime을 임의 이동하지 않는다. Git에는 저장소 .gitignore의 해당 root .wb/ 규칙을 기존 bytes 보존하여 추가하며 비Git에는 파일을 만들지 않는다.

BRIEF r0.4의 WI-D01~10은 개별 사용자 결정이다. WI-P01/P03~07와 SPEC의 기술·test seam 제안은 전체 bundle 확인 대기이며 이 ticket 파일의 존재가 승인은 아니다.
구체 write 범위는 PLAN의 `write_scope_hint`를 출발점으로 Root가 dispatch 직전 실제 base/dirty files와 대조한다. 기존 사용자 변경을 보존한다.

## 검증

고정된 사용자 폴더 트리·사전 hash·Git ls-files/check-ignore를 oracle로 context API를 behavior별 RED → 최소 GREEN. 권한·symlink·이미 추적된 .wb·ignore 실패·동시 marker 생성·runtime 소유자와 UDS 107-byte 상한을 검증한다. 기존 global-default assertion은 승인된 기본값 변경에 맞춰 바꾸되 flag/env 호환 assertion을 유지한다. G-WI-03은 실제 OMP/CLI 시작을 요구하지 않는다.

소유 gate: G-WI-03. required evidence level·supplier는 PLAN gate 항목을 따른다. 소유 gate는 자신의 산출물과 transitive predecessors만 요구하며 이후 통합 G-WI-10/11을 앞 ticket의 완료 조건으로 역참조하지 않는다.

예정 명령(이 planning에서는 실행하지 않음; 새 경로는 이 ticket 또는 명시된 prerequisite가 작성):

```sh
PYTHONPATH=src:. python3 -m unittest discover -s tests/backend/installation -p 'test_project*.py' -v
PYTHONPATH=src:. python3 -m unittest discover -s tests/backend/installation -p 'test_runtime_paths.py' -v
```

일반 behavior는 Root가 실제 `.agents/skills/tdd/SKILL.md` identity와 승인된 SPEC test seam을 packet에 넣어 한 행동의 RED → 최소 GREEN → 다음 행동 순서로 수행한다.
RED의 원인·당시 후보/명령, 최소 production delta, GREEN 후보/명령을 남긴다. unrelated import/도구 오류를 의미 있는 RED로 주장하지 않는다.
독립 test_designer는 worker 구현을 정답으로 복제하지 않고 승인된 요구·독립 expected values에서 검증을 평가/보완한다. coherence unit의 fresh general review와 최종 feature의 Standards/Spec pair, 해당 security review는 Root가 계약 §7에 따라 수행한다.

## 제외 범위와 중단 조건

사용자 파일을 덮어쓰거나 잘못된 .wb를 건너뛰어 다른 프로젝트로 연결하지 않는다. symlink data-dir/외부 소유 runtime·동일 UUID 복제/root 불일치를 정상으로 취급하지 않는다. 새 nested-init 명령은 추가하지 않는다.

새 제품 결정·test seam 변경·승인 범위 밖 의존성이 필요하면 Root에 근거와 영향 ticket/gate를 전달한다. leaf는 workflow 재진입·추가 위임하지 않는다.

## 결과 전달

candidate_id, attributable diff/산출 경로, 실제 사용한 contract/recipe, gate별 passed/failed/not_run/unknown, 명령/환경/버전과 TDD chronology 또는 정당한 예외·대체 근거를 전달한다.
probe는 가정 → 최소 실행 → 관측 결과 → 가능한 다음 범위를 분리한다. 실패·중단 기록과 잔존 소유 process·경로, 충돌/unknown 및 needs_oracle/needs_reroute를 숨기지 않는다. Root의 통합·검증 전 결과는 candidate이지 통합 완료가 아니다.
