# WI-05: 프로젝트별 시작·재접속과 기존 CLI 호환

Specification: [SPEC.md s1](../SPEC.md). Scheduling: [PLAN.json p1](../PLAN.json)의 `WI-05` 항목이 유일한 dependency/resource 원본이다.

## 제공 동작

wb 무인자는 start/attach로 이어지고 하위 폴더에서도 동일 backend와 host project root를 사용한다. 서로 다른 project는 backend·Task·raw/important logs·OMP sessions가 섞이지 않는다. 부족한 요건은 setup 안내로 멈추며 --data-dir/환경 변수/기존 omp-workbench 세부 명령을 유지한다.

산출물: wb 기본 실행과 기존 CLI가 root/cwd/runtime/data identity를 일관되게 사용하며 두 프로젝트를 격리.

## 계약과 관련 맥락

WI-03 context/layout, WI-04 setup 선택, WI-02 자산을 소비한다. frontend와 backend/bridge/UI가 같은 runtime endpoints 및 project identity를 공유한다. 설치 Python은 WB 모듈을 실행하고 host persistent shell의 프로젝트 환경은 보존한다. legacy data-dir은 기존 lock/record/socket과 대조해 연결하며 실행 중 강제 이전하지 않는다. 기존 authentication link와 OMP variable session state 위치를 유지/분리한다.

BRIEF r0.4의 WI-D01~10은 개별 사용자 결정이다. WI-P01/P03~07와 SPEC의 기술·test seam 제안은 전체 bundle 확인 대기이며 이 ticket 파일의 존재가 승인은 아니다.
구체 write 범위는 PLAN의 `write_scope_hint`를 출발점으로 Root가 dispatch 직전 실제 base/dirty files와 대조한다. 기존 사용자 변경을 보존한다.

## 검증

CLI subprocess와 UiClient 공개 seam의 fixture RED → 최소 GREEN 후 G-WI-06 실프로세스 검증. 동일 project 동시 시작 1 backend, subdir reuse, A/B 격리, 긴 경로, explicit legacy 실행/접속, mismatched root/PID 부정 사례, detach/reattach·pause·shutdown을 관측한다. loopback scripted provider와 fake auth store만 쓰며 signal/timeout 후 소유 process group 종료와 socket 잔존을 확인한다.

소유 gate: G-WI-06. required evidence level·supplier는 PLAN gate 항목을 따른다. 소유 gate는 자신의 산출물과 transitive predecessors만 요구하며 이후 통합 G-WI-10/11을 앞 ticket의 완료 조건으로 역참조하지 않는다.

예정 명령(이 planning에서는 실행하지 않음; 새 경로는 이 ticket 또는 명시된 prerequisite가 작성):

```sh
PYTHONPATH=src:. python3 -m unittest discover -s tests/backend/installation -p 'test_project_cli.py' -v
PYTHONPATH=src:. python3 tests/backend/installation/live_project_sessions.py --run-root <owned-run-root>
```

일반 behavior는 Root가 실제 `.agents/skills/tdd/SKILL.md` identity와 승인된 SPEC test seam을 packet에 넣어 한 행동의 RED → 최소 GREEN → 다음 행동 순서로 수행한다.
RED의 원인·당시 후보/명령, 최소 production delta, GREEN 후보/명령을 남긴다. unrelated import/도구 오류를 의미 있는 RED로 주장하지 않는다.
독립 test_designer는 worker 구현을 정답으로 복제하지 않고 승인된 요구·독립 expected values에서 검증을 평가/보완한다. coherence unit의 fresh general review와 최종 feature의 Standards/Spec pair, 해당 security review는 Root가 계약 §7에 따라 수행한다.

## 제외 범위와 중단 조건

root/record/PID 시작시각·소유권이 불일치하거나 수명 unknown이면 잘못된 attach·자동 실행·강제 종료를 보류한다. runtime 분리로 pause/no replay/로그 보호를 완화하지 않는다. 사용자의 실제 backend나 실험을 테스트에 쓰지 않는다.

새 제품 결정·test seam 변경·승인 범위 밖 의존성이 필요하면 Root에 근거와 영향 ticket/gate를 전달한다. leaf는 workflow 재진입·추가 위임하지 않는다.
