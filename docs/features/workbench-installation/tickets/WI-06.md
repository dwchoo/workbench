# WI-06: 원본을 보존하는 중단 상태 data-dir 이관

Specification: [SPEC.md s1](../SPEC.md). Scheduling: [PLAN.json p1](../PLAN.json)의 `WI-06` 항목이 유일한 dependency/resource 원본이다.
상태: bundle 승인 대기인 계획 초안. 실행 상태·writer·후보·검증은 Root의 `.workflow/workbench-installation/` 기록에서 관리한다.

## 제공 동작

wb migrate --from <legacy-data-dir> --project <project-root>는 source/target 쓰기가 중단된 경우에만 빈 대상 .wb로 복사한다. 성공 후 새 상태를 사용할 수 있고 원본과 원본의 이력을 그대로 보존한다. 실패·중단 대상은 정상 project로 탐색되지 않는다.

산출물: 중단 확인·복사·무결성/재오픈 검증·경로 재연결·완료 marker를 가진 wb migrate.

## 수락 기준

WI-AC-09, WI-AC-10, WI-AC-12, WI-AC-15. [SPEC의 전체 acceptance trace](../SPEC.md#수락-기준)의 해당 행을 적용하며 생략하지 않는다.
이 ticket의 local 관측과 후속 integration 관측을 구분한다. 완료 표시만으로 사용자 수락을 충족하지 않는다.

## 계약과 관련 맥락

SPEC §이관 transaction과 WI-05 backend identity/legacy 동작을 소비한다. source는 read-only로 관측하며 SQLite는 read-only snapshot/backup으로 WAL 포함 일관성을 확보한다. 원문 log/history는 보존하고 operational storage 참조만 명시적 mapping으로 재결합한다. auth 링크는 따라 복사하지 않고 기존 사용자 store에 새로 연결한다. 과거 승인·PID·socket·boot 상태는 새 실행권한이 아니다.

BRIEF r0.4의 WI-D01~10은 개별 사용자 결정이다. WI-P01/P03~07와 SPEC의 기술·test seam 제안은 전체 bundle 확인 대기이며 이 ticket 파일의 존재가 승인은 아니다.
구체 write 범위는 PLAN의 `write_scope_hint`를 출발점으로 Root가 dispatch 직전 실제 base/dirty files와 대조한다. 기존 사용자 변경을 보존한다.

## 검증

public migrate CLI에서 알려진 Task/command/run IDs, legacy/new raw bytes, important DB와 OMP sessions의 독립 fixture를 behavior별 RED → 최소 GREEN으로 확인한다. source 전체 hash/mtime·DB row·log bytes oracle, 대상 reader reopen과 새 start의 no replay를 대조한다. running/unknown owner, target 이력/빈 legacy 충돌, symlink/중첩, disk-full·복사중단·corrupt DB·경로누락·외부worktree 참조·동시 start 경합을 포함한다. G-WI-08은 실제 중단→이관→재시작·읽기까지 관측한다.

소유 gate: G-WI-07, G-WI-08. required evidence level·supplier는 PLAN gate 항목을 따른다. 소유 gate는 자신의 산출물과 transitive predecessors만 요구하며 이후 통합 G-WI-10/11을 앞 ticket의 완료 조건으로 역참조하지 않는다.

예정 명령(이 planning에서는 실행하지 않음; 새 경로는 이 ticket 또는 명시된 prerequisite가 작성):

```sh
PYTHONPATH=src:. python3 -m unittest discover -s tests/backend/installation -p 'test_migration.py' -v
PYTHONPATH=src:. python3 tests/backend/installation/live_migration.py --run-root <owned-run-root>
```

일반 behavior는 Root가 실제 `.agents/skills/tdd/SKILL.md` identity와 승인된 SPEC test seam을 packet에 넣어 한 행동의 RED → 최소 GREEN → 다음 행동 순서로 수행한다.
RED의 원인·당시 후보/명령, 최소 production delta, GREEN 후보/명령을 남긴다. unrelated import/도구 오류를 의미 있는 RED로 주장하지 않는다.
독립 test_designer는 worker 구현을 정답으로 복제하지 않고 승인된 요구·독립 expected values에서 검증을 평가/보완한다. coherence unit의 fresh general review와 최종 feature의 Standards/Spec pair, 해당 security review는 Root가 계약 §7에 따라 수행한다.

## 제외 범위와 중단 조건

검증할 수 없는 내부 storage 참조나 DB schema는 성공으로 넘기지 않는다. 외부 결과와 Git worktree를 임의로 이동/등록/정리하지 않고 원본 참조를 유지하며 미접근 상태를 표시한다. unknown file을 조용히 누락하거나 임의 실행파일을 실행하지 않는다. 병합/live 이동/원본 삭제는 제외한다.

새 제품 결정·test seam 변경·승인 범위 밖 의존성이 필요하면 Root에 근거와 영향 ticket/gate를 전달한다. leaf는 workflow 재진입·추가 위임하지 않는다.
