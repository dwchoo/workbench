Specification: [SPEC.md s1](../SPEC.md). Scheduling: [PLAN.json p1](../PLAN.json)의 `WI-08` 항목이 유일한 dependency/resource 원본이다.

## 제공 동작

현재 후보를 임시 local Git ref와 wheel/sdist에서 noneditable uv tool 설치하고 source 접근·PYTHONPATH 없이 설치→setup→프로젝트 A/B→subdir 재접속→detach/pause/shutdown→이관→새 상태 조회를 검증한다. 외부 원격 push나 실제 사용자 데이터 이관은 수행하지 않는다.

산출물: 전체 수락 기준에 대한 현재 설치 후보의 runtime 증거·독립 test assessment·Standards/Spec/security 리뷰와 최종 보고.

## 검증

Root가 독립 test_designer를 통해 요구에서 도출한 반례/expected values를 먼저 평가하고 필요한 통합 tests를 보완한다. 전체 후보를 고정한 후 fresh Standards와 Spec reviewer 두 context 및 별도 security reviewer, diff secret scan을 수행한다. lockfile 변경 때 dependency audit도 요구한다. 기존 관련 Python/TS 회귀와 최소 실제 SDK 경로·Manager report/Worker 미노출 경계를 재검증한다. 이 ticket은 이전 TDD chronology를 사후 만들어내지 않는다.

소유 gate: G-WI-10, G-WI-11. required evidence level·supplier는 PLAN gate 항목을 따른다. 소유 gate는 자신의 산출물과 transitive predecessors만 요구하며 이후 통합 G-WI-10/11을 앞 ticket의 완료 조건으로 역참조하지 않는다.

예정 명령(이 planning에서는 실행하지 않음; 새 경로는 이 ticket 또는 명시된 prerequisite가 작성):

```sh
PYTHONPATH=src:. python3 tests/integration/live_workbench_installation.py --run-root <owned-run-root>
<recorded-node> --experimental-strip-types --test tests/bridge/*.test.ts
```

일반 behavior는 Root가 실제 `.agents/skills/tdd/SKILL.md` identity와 승인된 SPEC test seam을 packet에 넣어 한 행동의 RED → 최소 GREEN → 다음 행동 순서로 수행한다.
RED의 원인·당시 후보/명령, 최소 production delta, GREEN 후보/명령을 남긴다. unrelated import/도구 오류를 의미 있는 RED로 주장하지 않는다.
독립 test_designer는 worker 구현을 정답으로 복제하지 않고 승인된 요구·독립 expected values에서 검증을 평가/보완한다. coherence unit의 fresh general review와 최종 feature의 Standards/Spec pair, 해당 security review는 Root가 계약 §7에 따라 수행한다.

## 제외 범위와 중단 조건

필수 runtime·security check not_run은 pass가 아니다. 실제 사용자 HOME/OMP auth·backend 접근, source-only PYTHONPATH로 설치 실패를 숨김, 미확인 Linux/arch/outer multiplexer를 보장하는 보고를 금지한다. prerequisite 실패는 실패 원인 ticket으로 제한된 수정 후 affected 검증만 다시 수행한다. commit/push/게시·서비스 등록·사용자 데이터 이관은 별도 요청 없이는 하지 않는다.

새 제품 결정·test seam 변경·승인 범위 밖 의존성이 필요하면 Root에 근거와 영향 ticket/gate를 전달한다. leaf는 workflow 재진입·추가 위임하지 않는다.
