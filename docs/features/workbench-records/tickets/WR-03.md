# WR-03: 문자열 검색·목록·이력과 사용자 조회 CLI

명세: [SPEC.md s1](../SPEC.md). Scheduling·의존성·resource·write scope·gate supplier 정본: [PLAN.json p1](../PLAN.json)의 `WR-03` 항목. 상태·실제 assignment는 Root 운영 기록에서만 관리한다.

## 제공할 동작

같은 저장소의 최신 기록 목록, literal 제목·본문 검색, revision metadata 목록과 cursor를 제공한다. 사용자에게 `wb records list|search|show|history`를 연결한다. 조회는 DB·project를 자동 생성하거나 backend/model을 시작하지 않는다.

## 수락 기준

WR-AC-09·12의 로컬 조회·CLI 부분, WR-G03-query-cli를 담당한다. 두 역할의 같은 조회 경로와 실제 OMP는 후속 결합 검증이다.

## 계약과 근거

SPEC s1의 최신본 검색·대소문자 구분 literal substring·정렬·한도·cursor·status와 CLI context 해석을 따른다. Task filter는 현재 프로젝트 안의 선택적 filter다. History는 metadata, 본문은 show로 조회한다. DB 부재의 빈 결과와 접근 불가를 구분한다.

Frozen get/revision 계약은 그대로 유지한다. Markdown exporter는 이 계약만 소비하므로 조회 API 구현이나 CLI가 완성되지 않아도 독립 구현할 수 있다. 구현 중 get 의미를 바꾸면 그 독립성이 깨지므로 Root에 알린다.

## 검증

한 동작씩 public RED→최소 GREEN을 반복한다. 직접 지정한 두 프로젝트·record ID·revision·본문으로 최신본만 검색되는지, 한글/`%`/`_`/인용부호가 literal인지, cursor가 누락/잘못된 값일 때의 구분, 저장 시각 tie-break와 page 경계를 확인한다. CLI는 subprocess로 실제 parser·cwd·명시 data-dir·exit·JSON을 관측한다.

예정 명령:

- `PYTHONPATH=src python3 -m unittest tests.storage.work_records.test_query`
- `PYTHONPATH=src python3 -m unittest tests.backend.work_records.test_cli`
- `PYTHONPATH=src python3 -m unittest tests.storage.work_records.test_store`

독립 expected value는 test가 손으로 정한 검색 hit 목록·revision·프로젝트별 sentinel이다. 구현의 SQL/cursor helper를 호출해 예상 결과를 만들지 않는다. 실제 OMP는 검증하지 않는다. U3에서 WR-04와 함께 test_designer 독립 평가·fresh general review를 받으며 WR-05가 소비하기 전에 합친 계약을 동결한다.

## 비목표와 중단 조건

의미 검색·FTS dependency·새 service·export CLI는 추가하지 않는다. 정상 조회가 기록을 변경하거나 타 프로젝트 자료를 반환하면 요구 결함이다. 사용자 상태를 초기화/이관해 테스트를 통과시키지 않는다.

## 허용 변경과 출력 handoff

계획의 `write_scope_hint` 안에서 동작과 검증을 함께 작성한다. 테스트를 전부 먼저 쓰거나 구현/테스트를 서로 다른 worker에 일괄 분리하지 않는다. Root는 dispatch 때 실제 기반 후보·TDD reference identity·공개 seam·허용 경로·명령을 재확인한다. Scope 확대가 필요하면 변경 전에 이유와 영향을 전달한다. 동시 writer는 검증된 격리 workspace와 호환 resource가 있을 때만 허용한다.

Candidate ID·변경 경로·정확한 command/result·독립 expected value·미검증 한계와 각 행동의 RED 원인/당시 후보→최소 변경→GREEN 후보/명령을 전달한다. Probe/문서 등 정당한 예외는 이유·대체 근거를 남긴다. 결과는 candidate_ready/needs_reroute/needs_oracle/blocked 중 실제 상태와 근거를 사용하며 그 flag만으로 통합·수락을 주장하지 않는다. Commit·게시·배포하지 않는다.
