# WR-04: 지정 revision의 Markdown 사본 생성

명세: [SPEC.md s1](../SPEC.md). Scheduling·의존성·resource·write scope·gate supplier 정본: [PLAN.json p1](../PLAN.json)의 `WR-04` 항목. 상태·실제 assignment는 Root 운영 기록에서만 관리한다.

## 제공할 동작

동결된 get snapshot을 Markdown 파일로 출력하는 `export_record`를 제공한다. 최신/지정 revision·출처 metadata를 보존하고 요청한 기존 파일을 덮어쓰지 않는다. 이 ticket은 public exporter이며 사용자 CLI 연결은 후속 통합 ticket의 범위다.

## 수락 기준

WR-AC-02·10·12의 파일 출력·실패 경계와 WR-G04-markdown-snapshot을 담당한다. OMP export tool/사용자 CLI 전체는 결합 검증에서 확인한다.

## 계약과 근거

SPEC s1의 ID 1건·선택적 revision·존재하는 부모 디렉터리·배타 leaf 생성·0600·본문 유지·상대 경로 기준을 따른다. Exporter는 명시적으로 확정한 absolute destination과 snapshot을 받으며 상대 경로의 사용자 맥락 해석은 호출 adapter의 책임이다. Title·ID·revision·생성/저장 시각·Task metadata 뒤에 저장 본문을 제공한다.

기존 report helper는 충돌 시 다른 파일명을 고르는 별도 계약이므로 그대로 재사용하지 않는다. DB를 export 경로로 선택하거나 DB와 충돌하는 경우 원본을 보존하며 실패한다. 파일로 내보낸 뒤 수정해도 DB에 되쓰기하지 않는다.

## 검증

한 행동의 RED→최소 GREEN 뒤 다음 행동으로 간다. 실제 임시 파일시스템에서 최신/과거 snapshot, Unicode 경로, 기존 일반 파일·symlink sentinel, 부모 부재·권한/쓰기 실패와 부분 출력 정리를 확인한다. 실패 시 기존 DB·정상 파일을 보존하고 불명 cleanup을 성공으로 표시하지 않는다.

예정 명령: `PYTHONPATH=src python3 -m unittest tests.storage.work_records.test_exporter tests.storage.work_records.test_store`.

Expected value는 직접 작성한 두 revision의 본문·metadata와 sentinel bytes다. 전체 exporter 출력을 그 exporter의 formatter로 다시 만들어 비교하는 mirror test는 사용하지 않는다. 이 seam은 OMP의 자연어/경로 의도 해석을 증명하지 않는다. U3 test_designer·fresh general review와 최종 path security packet 대상이다.

## 비목표와 중단 조건

저장/조회 계약·CLI parser·bridge 파일을 수정하지 않는다. 디렉터리 자동 생성·덮어쓰기 옵션·양방향 동기화·자동 파일명 fallback은 추가하지 않는다. Frozen get/revision을 변경해야 하면 Root로 돌린다.

## 허용 변경과 출력 handoff

계획의 `write_scope_hint` 안에서 동작과 검증을 함께 작성한다. 테스트를 전부 먼저 쓰거나 구현/테스트를 서로 다른 worker에 일괄 분리하지 않는다. Root는 dispatch 때 실제 기반 후보·TDD reference identity·공개 seam·허용 경로·명령을 재확인한다. Scope 확대가 필요하면 변경 전에 이유와 영향을 전달한다. 동시 writer는 검증된 격리 workspace와 호환 resource가 있을 때만 허용한다.

Candidate ID·변경 경로·정확한 command/result·독립 expected value·미검증 한계와 각 행동의 RED 원인/당시 후보→최소 변경→GREEN 후보/명령을 전달한다. Probe/문서 등 정당한 예외는 이유·대체 근거를 남긴다. 결과는 candidate_ready/needs_reroute/needs_oracle/blocked 중 실제 상태와 근거를 사용하며 그 flag만으로 통합·수락을 주장하지 않는다. Commit·게시·배포하지 않는다.
