# WR-06: 새 세션 미리보기·기록 지침·CLI export

명세: [SPEC.md s1](../SPEC.md). Scheduling·의존성·resource·write scope·gate supplier 정본: [PLAN.json p1](../PLAN.json)의 `WR-06` 항목. 상태·실제 assignment는 Root 운영 기록에서만 관리한다.

## 제공할 동작

실제 주 session startup/switch에 최근 기록의 제목·미리보기를 자동 제공하고 본문은 필요할 때 읽게 한다. 두 역할의 상시 prompt에 일반 기록은 DB, 정식 문서는 파일, Markdown은 명시 요청으로 출력한다는 지침을 연결한다. 사용자 CLI의 export subcommand를 exporter에 연결한다.

## 수락 기준

WR-AC-02·03·04·05·06·09·10·12의 결합 경계다. WR-G06-session-preview는 실제 OMP runtime, WR-G07-policy-cli는 fixture 수준이다. Runtime이 없으면 fixture만으로 완료 처리하지 않는다.

## 계약과 근거

SPEC s1의 recent 5건·preview160자·전체16 KiB 한도·더 있는지 표시·원본문 보존을 따른다. 공개 API는 WR-01에서 판별된 경로만 사용한다. Session/generation·현재 연결을 결속하고 reconnect 반복 주입과 switch 전 지연 응답 혼입을 막는다. `triggerTurn:false`/동등 공개 경로로 추가 모델 작업을 만들지 않고 pause·기존 사용자 입력 경계를 유지한다.

지침은 짧은 상시 prompt와 도구 설명으로 연결하며 기존 Manager/Worker 역할·report skill 계약을 바꾸지 않는다. 명시적인 기록을 자동 중요 로그로 대체하지 않는다. `wb records export`는 CLI cwd, 도구 export는 backend 프로젝트 root를 기준으로 상대 경로를 해석한다.

## 검증

검증 가능한 동작은 한 행동의 RED→최소 GREEN 뒤 다음으로 진행한다. 먼저 extension stand-in에서 session key·stale response·한도·중복·empty/unavailable을 검증한 뒤 실제 OMP runtime에서 같은 차이를 관측한다. 첫 입력과 startup 경합·session switch·pause를 각각 확인하며 provider 요청 payload/횟수·UI 표시를 구분해 남긴다.

예정 명령:

- `node --experimental-strip-types --no-warnings --test tests/bridge/work_records_context.test.ts`
- `PYTHONPATH=src python3 -m unittest tests.backend.work_records.test_prompt_policy tests.backend.work_records.test_cli_export`
- `WB_LIVE_RECORDS=1 PYTHONPATH=src python3 -m unittest tests.backend.work_records.live_session_context_probe`
- `PYTHONPATH=src python3 -m unittest tests.backend.test_workbench_skills`
- `PYTHONPATH=src python3 -m unittest discover -s tests/backend/workbench_report -p 'test_*.py'`

Expected value는 독립 canary·새/이전 session별 목록·직접 정한 revision/파일·기존 role policy다. Scripted provider는 상시 지침/도구/preview가 실제 context에 들어가고 실행되는 경로를 증명하며 실제 모델의 의도 해석 품질로 포장하지 않는다. U4 test_designer 평가·fresh general review 후 WR-07에 공급한다. 상시 지침 문구는 문서/설정 성격에 맞는 검사로 확인하고 불필요한 가짜 RED를 만들지 않는다.

## 비목표와 중단 조건

새 모델 점검·Task·자발적 Manager 보고·상주 agent를 추가하지 않는다. 공개 API가 약속한 표시/context/turn 경계를 만족하지 못하면 근거를 Root에 전달한다. Preview 제거·사용자 수동 조회 강제·유료 모델 호출로 조용히 우회하지 않는다.

## 허용 변경과 출력 handoff

계획의 `write_scope_hint` 안에서 동작과 검증을 함께 작성한다. 테스트를 전부 먼저 쓰거나 구현/테스트를 서로 다른 worker에 일괄 분리하지 않는다. Root는 dispatch 때 실제 기반 후보·TDD reference identity·공개 seam·허용 경로·명령을 재확인한다. Scope 확대가 필요하면 변경 전에 이유와 영향을 전달한다. 동시 writer는 검증된 격리 workspace와 호환 resource가 있을 때만 허용한다.

Candidate ID·변경 경로·정확한 command/result·독립 expected value·미검증 한계와 각 행동의 RED 원인/당시 후보→최소 변경→GREEN 후보/명령을 전달한다. Probe/문서 등 정당한 예외는 이유·대체 근거를 남긴다. 결과는 candidate_ready/needs_reroute/needs_oracle/blocked 중 실제 상태와 근거를 사용하며 그 flag만으로 통합·수락을 주장하지 않는다. Commit·게시·배포하지 않는다.
