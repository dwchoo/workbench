# WU-02: 작업 확인·종료·백업·재개를 포함한 update 수직 구현

명세: ../SPEC.md s1. Scheduling·의존성·resource·write scope·gate supplier: ../PLAN.json p1의 WU-02. 상태·실제 assignment는 Root 운영 기록에서만 관리한다.

## 제공할 동작

WU-01에서 판별된 runner로 공개 update를 연결한다. idle 자동 업데이트부터 active 확인/거절, 승인 종료, 검증된 private backup/재개 안내, 실패/경합까지 한 행동씩 개발한다.

## 수락 기준·계약

WU-AC-01, WU-AC-02, WU-AC-03, WU-AC-04, WU-AC-05, WU-AC-06, WU-AC-07, WU-AC-08와 SPEC s1의 공개 seam·보존·실패 계약을 따른다. PLAN의 해당 ticket을 owner로 하는 gate 및 선행 gate를 충족한다.

## 검증

SPEC의 공개 CLI/실제 filesystem·DB/설치본 seam과 독립 sentinel·hash·process identity를 사용한다. 동작마다 RED→최소 GREEN 후 다음 동작으로 진행한다. Probe/문서의 예외는 실제 이유·대체 근거를 기록한다. Test_designer는 요구에서 먼저 도출하고 기존 coverage를 재사용하며 실제 gap만 추가한다. 동일 후보/환경의 통과 근거를 반복 실행하지 않는다. 실제 runtime을 mock 성공으로 대체하지 않는다.

 `PYTHONPATH=src python3 -m unittest discover -s tests/backend/maintenance -p 'test_update*.py'`; `PYTHONPATH=src:tests/backend/installation python3 -m unittest tests.backend.test_paths_launcher tests.backend.installation.test_project_cli`; `WB_LIVE_UPDATE=1 PYTHONPATH=src python3 -m unittest tests.integration.live_workbench_update`. installed test는 checkout 밖 실행·실제 uv/Git·localhost scripted OMP·private data만 사용한다. 누락된 필수 runtime을 fixture로 대체하지 않는다.

## 중단·범위

사용자 데이터/auth/global 설치/실제 연구 process·유료 provider·Docker·새 도구 설치·모델 전환·중첩 위임을 사용하지 않는다. source/실행/backup 결과 불명은 Root에 근거와 함께 보고한다. 합의된 복구·보존·명시적 확인 의미를 바꾸지 않는다. 개별 leaf의 commit/push/공유 ledger/lifecycle 조작은 금지하며 Root가 최종 검증 뒤 게시한다.
